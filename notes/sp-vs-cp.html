0摘要与核心结论

SP 与 CP 都「沿序列维切」，这是它们被混为一谈的根源。但两条线的出身、切的对象、代价形态完全不同：

一句话区分： SP（Sequence Parallelism）切「按 token 独立的算子」的激活（LayerNorm / Dropout / 残差）， 注意力原样不动——它是 TP 的配套优化，省激活显存，只能节点内； CP（Context Parallelism）切「KV cache 与注意力计算」本身， 每个 rank 只持有序列的一段 KV、只算自己那段的注意力分数——它是独立的并行维度， 解决KV 放不下 / 超长 prefill，可跨节点，需要跨块 softmax（LSE）合并。

核心结论（先给答案）

  • SP 是 TP 的「衍生品」，CP 是「原生维度」。SP 只有在 TP>1 时才有意义（它优化的是 TP 的激活冗余）；CP 从设计上独立于 TP/PP/DP，可以和任何并行度相乘。
  • SP 不切注意力，CP 切注意力。SP 下每个 rank 仍持有全序列的 q/k/v 并计算完整 score（只是 norm/dropout/残差按序列分片）；CP 下每个 rank 只持有 S/P 的 KV，score 只覆盖自己的块，最终靠 online softmax / LSE 合并。这是两者最本质的分水岭。
  • SP 的通信是「替换」，CP 的通信是「新增」。SP 把 TP 的 all-reduce 换成 reduce-scatter + all-gather，总量同阶（vLLM enable_sp 原文：AllReduce → ReduceScatter + AllGather，不直接提性能，是 AsyncTP 的前置）；CP 的 ring / all-to-all 是 TP 之外的额外通信，随序列长度线性增长。
  • 命名是重灾区。Megatron 的「SP」与部分框架里被叫做「sequence parallel」的注意力切分（其实是 CP）完全是两回事；反之 DeepSeek 说的「CP」、vLLM 的「CP（PCP/DCP）」、SGLang 的 --cp 指同一类。读文档先确认它切的是「激活」还是「KV/注意力」。
  • 两者可以叠加。长上下文 + 大 batch 的部署常见组合：TP 切头（+SP 省激活显存）负责节点内算力与显存，CP 负责跨节点把 KV 摊开——vLLM 文档的「先 TP 后 DCP」就是这个顺序。

1来龙去脉：两条独立演化线

1.1 SP 的起源：TP 的激活冗余问题（2023，Megatron-LM）

2019 年 Megatron-LM 发明 TP 时，注意力在 TP 下的激活是每卡复制的：输入激活 [B,S,H] 在 P 张卡上各持一份，列并行/行并行只切权重。这意味着 LayerNorm、Dropout、残差这些「按 token 独立」的算子，每张卡都存了一份完整激活——冗余 P 倍。

2022-2023 年，序列变长、batch 变大，激活显存成为瓶颈。当时的主流解法是激活重计算（activation recomputation / gradient checkpointing）：不存激活、反向时重算——用算力换显存。Korthikanti 等人在 Reducing Activation Recomputation in Large Transformer Models（arXiv:2305.13245，2023）里提出第三条路：与其重算，不如把激活沿序列维切开——这就是 Megatron 的 Sequence Parallelism（SP）。

SP 的动机一句话：TP 把「权重」摊到了 P 张卡，却没把「激活」摊开——norm/dropout/残差的激活在每张卡重复存了 P 份。SP 把这部分也按序列维切开，每卡只存 1/P，从而在不增加重计算的前提下让 batch 或序列可以更大。

1.2 CP 的起源：长上下文放不下（2023，Ring / Ulysses）

几乎同一时期，另一条线从长上下文出发：上下文到 128K / 1M 时，KV cache 单卡放不下，而 TP 切头只能把 KV 按头切开、GQA 头少就切不动、MLA 的 latent 根本无法切（见 注意力 TP 报告）。2023 年两篇论文给出了「按序列切 KV」的方案：

  • Ring Attention（Liu et al., arXiv:2310.01889）：KV 块沿环形逐轮转发，每轮算「本地 query × 转来的 KV 块」，P−1 轮后全部 KV 都看过；
  • DeepSpeed-Ulysses（Jacobs et al., arXiv:2309.14509）：Q 按头、K/V 按序列切成块，一次 all-to-all 把需要的头换到位。

2024-2026 年进入生产引擎：vLLM 把 CP 细分为 PCP（prefill 上下文并行）与 DCP（decode 上下文并行），SGLang 提供 --cp（ring 后端），TensorRT-LLM 有 context parallel 模块，DeepSeek / GLM / Kimi 的 128K–1M 部署都依赖 CP（DeepSeek-V3.2 的稀疏注意力 DSA 则是另一条降低长上下文成本的路线，与 CP 互补）。

2SP 详解（Megatron 序列并行）

2.1 切的对象：只有「按 token 独立」的算子

Transformer 层里的算子分两类：

  • 按 token 独立（逐 token 算，token 之间无依赖）：LayerNorm、Dropout、残差加、SiLU·Mul 等 → 可以按序列维任意切分，每卡只算自己的 S/P 段；
  • 跨 token 依赖：QKV 投影（GEMM，无 token 依赖但需要全序列激活）、注意力 score/softmax（需要全序列）、行并行合并 → 不能简单按序列切。

SP 的巧妙之处：只切第一类，第二类用通信原语衔接——这正是它与 CP 的分水岭（CP 连第二类里的注意力也切了）。

2.2 机制：all-reduce → reduce-scatter + all-gather

SP 的通信替换（vLLM enable_sp 原文）AllReduce → ReduceScatter + AllGather　——　总量同阶，不新增通信，换来激活按序列分片

以 TP=4 的注意力路径为例（蓝 = 每卡 shape，S 为序列长）：

①输入 [S/P, H]（上一层以序列分片形式交过来）→ LayerNorm 在分片上算（SP 收益点：norm 激活不再每卡全量）
②QKV 列并行：[S/P,H] → [S/P, 3N/P]（输入分片，输出头分片）→ all-gather（沿序列） → [S, 3N/P]（attention 需要全序列）
③attention：每卡 本地头 × 全序列，score [B, h/P, S, S] —— 与标准 TP 完全相同，注意力没有被切分 → 输出 [S, H/P]
④O 行并行：[S,H/P] → 部分和 [S,H] → reduce-scatter（沿序列） → [S/P, H] → + 残差（分片上加）
⑤MLP：gate/up 列并行 [S/P,H]→[S/P,4H/P] → SiLU·Mul（逐元素，分片上）→ down 行并行 [S/P,4H/P]→部分和→all-reduce → [S/P,H] → + 残差 → 下一层

注：上表是 Megatron-LM 的标准 SP 布局（attention 前的 all-gather 与 attention 后的 reduce-scatter 是 SP 相对标准 TP 新增/替换的通信对）；具体到实现，vLLM 的 enable_sp 把 AllReduce→RMSNorm 的融合模式替换为 ReduceScatter→RMSNorm→AllGather（docs/design/fusions.md），再经 fuse_gemm_comms 把 reduce-scatter/all-gather 与相邻 GEMM 融合。

2.3 收益与代价

项SP 的效果说明
激活显存（norm/dropout/残差/部分 GEMM 输出）÷P每卡只存自己的 S/P 段——这是 SP 的全部意义
通信量同阶（≈TP）all-reduce 换成 reduce-scatter + all-gather，总量不变（部分通信发生在分片后的张量上，甚至略少）

3CP 详解（ring / Ulysses / PCP-DCP）

3.1 切的对象：KV cache 与注意力计算本身

CP 把序列切成 P 块、分到 P 张卡：每卡只持有 S/P 的 KV（以及 S/P 的 query），attention 的 score 只在自己那块上算，跨块的部分靠通信补齐，最终用 online softmax / LSE 合并（合并细节见 术语表 的 LSE 与上份对话的 softmax 讨论）。

3.2 两种主流机制

模式机制通信适用
Ring Attention（Liu 2023） KV 块沿环形逐轮转发，每轮算「本地 query × 转来的 KV 块」，P−1 轮后全部 KV 都看过；online softmax 逐块累积 每层每步 N−1 次 p2p，每轮转发一块 ≈ 2·B·S·H·(P−1)/P 字节 任意 P；SGLang / vLLM CP 的 ring 后端
Ulysses（Jacobs 2023） Q 按头、K/V 按序列切成块，一次 all-to-all 把需要的头换到位（头并行 × 序列分片） 每层一次 all-to-all ≈ 同量级 P 较小、组内高带宽；与 TP 头数整除性好

3.3 vLLM 的落地：PCP / DCP（以及「先 TP 后 DCP」原则）

  • PCP（prefill context parallel）：prefill 阶段按序列切分，加速长提示词首 token。vLLM 文档给出两种策略：Partial query, full KV（KV 全量 gather，short 场景）与 Partial query, partial KV（ring 式分块，KV 放不下时）；
  • DCP（decode context parallel）：decode 阶段沿序列 T 维切 KV cache（交织分块），消除 TP 的 KV 复制（MLA 在 TP=8 下 8× 冗余、GQA 在 tp>kv_heads 下 ×(tp/kv_heads) 冗余，DCP 把它们消掉）；
  • 约束：DCP 复用 TP 的卡，要求 tp_size % dcp_size == 0（详见 并行度报告 §6.3）。

3.4 代价：LSE 合并与每层通信

CP 的两种代价① 跨块 softmax 合并（online m/l 或 LSE 加权）；② 每层注意力都要跨卡通信，通信量随层数线性叠加 —— 只有 KV 真放不下时才启用

稀疏注意力（DSA）只保留 top-k token 的 KV，把 attention 通信量降一个数量级——它是 CP 的长上下文互补路线（见 并行度报告 §6.2）。

4.2 PCP 流程（vLLM：partial query + full KV —— CP 的第三种实现）

PCP（prefill context parallel）是 CP 的「gather 变体」：query 照常分片（S/P），但 KV 不做轮转——上下文 KV 先 all-gather 成每 rank 全量（T），注意力一次算完。它处在 SP 与 ring 之间：query 算力并行（像 ring）＋ KV 全量本地 + 零跨 rank LSE 合并（像 SP）。前提是 KV 小到复制可接受（MLA 场景；vLLM 的 PCP 目前绑定 MLA-only，见 pcp_manager.py）。逐阶段流程（query 分片 S/P、上下文/键全量 T；TP=P 叠加）：

5.1 组合示例（真实部署）

  • DeepSeek-V3 推理：注意力用 TP4 + SP（profile-data 口径）摊节点内权重与激活；长上下文（128K/1M）靠 CP/DCP 摊 KV——两条线各司其职；
  • vLLM 的「先 TP 后 DCP」：-tp 8 摊权重/算力（MLA 下 KV 复制 8×），再加 -dcp 8 沿 T 维切 KV 把复制消掉（见 并行度报告 §6.3）；

6实战决策与踩坑清单

6.1 决策要点

用 SP（激活显存是瓶颈）

TP>1 且 batch/序列被激活显存卡住、不想开激活重计算时：SP 把 norm/dropout/残差激活 ÷P，通信不增加。vLLM 里开 enable_sp（默认关，SM90 自动配置），也是 AsyncTP 的前置。

用 CP（KV 放不下 / 超长上下文）

上下文超过单卡 KV 容量、或长提示 prefill 太慢时：CP 把 KV 与注意力按序列摊开。vLLM：prefill 用 PCP、decode 用 DCP；注意 tp % dcp == 0 整除约束与 --cp-kv-cache-interleave-size 对齐。

两者一起用

超长上下文 + 大并发：TP+SP 负责节点内（权重、算力、激活），CP/DCP 负责跨节点 KV。顺序按 vLLM 原则：先 TP 摊权重，再 DCP 消 KV 冗余。

都别用（稀疏注意力替代）

如果瓶颈是 attention 的算力/通信而不是容量：DSA 类稀疏注意力（top-k）把每层 attention 成本降一个数量级，与 CP 互补甚至替代——DeepSeek-V3.2 就是这么把 128K 成本压下来的。

7结语：一句话记住 SP 与 CP

  • SP 是「把激活切开省显存」——TP 的配套，不碰注意力，节点内，通信不增。它回答的是「batch/序列变大后中间张量放不下」。
  • CP 是「把 KV 与注意力切开装长序列」——独立维度，跨节点，每层通信，需要 LSE 合并。它回答的是「序列太长，KV 与 attention 放不下」。
  • 判读口诀：切 norm/dropout/残差 = SP；切 KV/score = CP；都切 = 两者叠加。看到 "sequence parallel" 先确认它切了什么，再谈性能。
  • 演化趋势：SP 已基本内化为 TP 的默认配套（vLLM 的 enable_sp 编译 pass、Megatron 内建）；CP 是 2024 以来的长上下文主战场，正与稀疏注意力（DSA）在「谁更省」上竞争，并逐渐细分为 PCP/DCP 两阶段专用机制。
