前缀命中在 Transformer / MoE 中到底节省了什么计算

从「一句话结论」到「逐层 Shape 与 FLOPs 对照表」，系统梳理 Prefill、Decode 与投机解码三个阶段。

一句话结论：工程上说的“前缀命中”性能提升，绝大部分来自 KV Cache 复用了注意力（Attention）相关的计算——具体是 省掉“前缀 Token 之间的注意力分数（$Q \cdot K^{\top}$）与加权求和（$\mathrm{Softmax}\cdot V$）”，以及前缀 Token 的 Q/K/V 投影等逐层前向；而 MoE 的“专家路由命中”基本省不掉昂贵的 FFN，只省 Router 门控和权重加载。 投机解码则只作用于 Decode 阶段，靠“小模型猜、大模型验”减少大模型的串行调用次数。

0问题背景

自回归 Transformer 每生成一个新 Token，都要用当前 Query 去和所有历史 Token 的 Key/Value 做注意力运算。 如果每次都从头算整段上下文，代价随序列长度 平方级增长（$O(S^2)$）。因此推理引擎普遍缓存已算好的 K、V， 即 KV Cache；当新请求与已有前缀相同，还能跨请求复用（常被叫 Prefix Cache / Prompt Cache）。 本页要回答的是：“命中”那一刻，到底哪一步计算被省掉了？省了多少？

1前缀命中的核心：Attention（KV Cache）

这里的“前缀命中”默认指 KV Cache 命中，而不是模型参数的稀疏计算。

它主要节省 Transformer Decoder 的 Self-Attention 里、针对前缀 Token 的以下计算：

  • Key / Value 投影（$X W_K$、$X W_V$），以及前缀部分的 Query 投影（$X W_Q$）——因为旧 Token 的注意力输出已经算好，不再需要它们的 Q。
  • 注意力分数 $Q \cdot K^{\top}$ 和 加权求和 $\mathrm{Softmax}\cdot V$ 中，前缀 Token 之间的那一块。
  • Softmax 归一化 中前缀 Token 对应行的指数与约简。
  • 次要但关键：减少从 HBM 反复读取原始激活、反复写入 K/V 的显存带宽开销（Decode 阶段的主要瓶颈）。

一句话：把“从头计算前缀上下文语义关联”的串行计算，转化成了“从缓存读 K/V 并只算新 Token”的查表操作。

2.1 有命中时，输入 Shape 被“压缩”了

无命中时，Attention 矩阵是 $[B, H, S, S]$ 的方阵；有命中时，只需算新 Token 的 Query 对全部 Key 的分数， 变成 $[B, H, S_{new}, S]$。本质是把“总长度 × 总长度”压缩成“新长度 × 总长度”。

2.2 四处节省

  • ① Q/K/V 投影：只算 $S_{new}$ 个 Token，省 $3\,B\,S_{hit}\,d_{model}^{2}$（含 $W_Q$，见上）。
  • ② 注意力分数 $Q \cdot K^{\top}$：从 $[B,H,S,S]$ 降到 $[B,H,S_{new},S]$，省的是左上“前缀×前缀”方块 $[B,H,S_{hit},S_{hit}]$。
  • ③ 加权求和 $\mathrm{Softmax}\cdot V$：从 $[B,H,S,S]$ 降到 $[B,H,S_{new},S]$，同样省前缀×前缀块。
  • ④ Softmax：从 $B H S$ 行降到 $B H S_{new}$ 行，省 $B H S_{hit}$ 行的 exp/求和/除法。
关键点：精确到块

注意力真正省下的是前缀×前缀块。在因果掩码下，注意力分数矩阵只算下三角，省下的分数块严格是 $\dfrac{S_{hit}(S_{hit}+1)}{2}$ 个元素（即 $\Theta(S_{hit}^{2})$）；若用“方阵”近似，省下的可写作 $\Theta(S_{hit}\cdot S)$（它已经包含了 $S_{hit}^2$ 项）。 注意：新 Token 对前缀 Token 的“交叉注意力”（左下 $[S_{new}, S_{hit}]$ 块）仍然要实时计算， 只是 K/V 从缓存读，省的是带宽与重算，而不是这次注意力本身。

3MoE 专家路由命中到底省什么

MoE 里有两种容易被混淆的“前缀命中”：

  • 语义前缀命中（Prompt Cache）：整个 Prompt 复用，Attention + FFN 全部免算，收益最大。
  • 专家路由命中（Routing Pattern Hit）：当前 Token 命中了与历史相同的 Top-K 专家组合。

对于“专家路由命中”，准确结论是：

  • 路由命中只省 Router（Gate）门控：$O(S \times E \times d_{model})$，以及未命中专家权重的加载（内存 IO）。
  • 省不掉 FFN 矩阵乘法：即使专家 ID 相同，新 Token 的数值特征不同，仍必须用 $W_1, W_2$ 乘新的输入 $X_{new}$。
  • FFN 的真实计算量是 $O(S \times d_{model} \times d_{ff})$，而不是 $O(S \times d_{model}^2)$（要含扩张系数 $d_{ff}$）。
三种情况的省法对照
文本前缀命中（KV Cache）：省 $Q\!\cdot\!K^{\top}$ 与 $\mathrm{Softmax}\!\cdot\!V$，$\Theta(S_{hit}\cdot S\cdot D)$（因果下精确为前缀×前缀块 $\Theta(S_{hit}^2\cdot D)$）。

MoE 路由命中：省 Router 门控 $O(S\cdot E\cdot d_{model})$，不省 FFN。

MoE 批量前缀命中（连续 Token 走同一专家）：省 Kernel 启动与权重加载延迟，而非 FLOPs。

  1. KV Cache 省的是“平方级”注意力：最大收益来自 Step 4 / Step 7 把 $O(S^2)$ 降到 $O(S_{new}\cdot S)$；序列越长越压倒性。

6投机解码为什么只在 Decode

投机解码（Speculative Decoding）几乎只能在 Decode 阶段生效，且优化目标和 KV Cache 完全不同。

  • Prefill 的本质是并行 GEMM：一次性处理整个 Prompt，GPU 利用率接近 100%，没有“生成”动作，无从猜起。
  • Decode 的本质是串行 GEMV：每步只生成 1 个 Token，瓶颈在显存带宽，GPU 利用率常低于 30%。
  • 投机解码靠“猜-验”：小模型（Draft）快速生成 m 个候选，大模型（Target）一次性并行验证，接受/拒绝后更新 KV Cache。

6.1 普通 Decode vs 投机解码（核心公式）

普通 Decode 生成 N 个 Token：$\mathrm{TotalFLOPs}_{normal}=N\times\big(\mathrm{Attention}(S_t)+\mathrm{MoE\_FFN}+\mathrm{Router}\big)$

投机解码（Draft 长 m、接受率 α）：$\mathrm{TotalFLOPs}_{spec}=\dfrac{N}{\alpha m}\times\mathrm{Target\_Verify}(m,S)+N\times\mathrm{Draft\_Model}(1)$

加速比：$\mathrm{Speedup}\approx\dfrac{N\cdot \mathrm{Cost}_{Target}(1)}{\frac{N}{\alpha m}\cdot \mathrm{Cost}_{Target}(m)+N\cdot \mathrm{Cost}_{Draft}(1)}$

当接受率 α 较高、Draft 模型足够小（$\mathrm{Cost}_{Draft}\ll\mathrm{Cost}_{Target}$）时，加速比趋近 α·m。 更精确地说，单轮（Draft 长 m、逐 Token 接受率 α、近似 i.i.d.）的期望接受 Token 数是 $\dfrac{1-\alpha^{m+1}}{1-\alpha}$（例如 α=0.8、m=5 时约 3.69 个，而非理想化的 4 个）。

7关键洞察与总结

  • 前缀命中（KV Cache）省的是 Self-Attention 里针对前缀 Token 的 $Q\!\cdot\!K^{\top}$、$\mathrm{Softmax}\!\cdot\!V$、Softmax 行，以及 Q/K/V 投影等逐层前向；核心收益是平方级的注意力节省，加一层线性的逐 Token 前向节省。
  • Shape 视角：注意力矩阵从 $[B,H,S,S]$ 压成 $[B,H,S_{new},S]$；省掉的是左上“前缀×前缀”块，新 Token 对前缀的交叉注意力仍要算（读缓存 K/V）。
  • MoE 路由命中只省门控与权重加载，省不掉 FFN。
  • 投机解码只在 Decode 生效，靠减少大模型串行调用次数换吞吐，理想加速比 $\alpha m$。
