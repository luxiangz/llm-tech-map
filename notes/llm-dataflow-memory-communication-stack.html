§0摘要与阅读方式

大模型里的「数据」从被算出来，到被另一个节点用上，要经过一串步骤： 算出来 → 存到哪 → 选什么语义搬 → 怎么找到对方 → 谁下单 → 谁搬字节 → 走哪条链路 → 怎么确认搬完了。 本文把这串步骤抽象成 8 个 Step（0~7），把 MemFabric / MemCache / Mooncake / TransferEngine / DeepEP / NCCL / NVLink / GPUDirect RDMA / CXL / LMCache / SHMEM / HiXL 等概念，按「它属于哪个步骤、在该步骤里回答什么问题」归位。

阅读路径：先读 §1 建立三类基础语义的认知 → 再看 §2 的分层视角（基础设施层 / 执行层 / 应用层）→ 然后读 §3 数据流总览，按 §4 的 Step 0~7 逐个展开 → 最后用 §5 跨栈对照和 §6 术语速查兜底。

核心观察：同一个技术名词常常只覆盖这串流程里的某 1~2 步。例如 NCCL 主要管「选语义 + 走链路」，Mooncake TransferEngine 主要管「单边传输语义 + 走 RDMA/TCP」。把不同步骤的概念放在一起比「谁快谁慢」，往往会比错对象。

1.2 三种基础语义：load/store · RDMA 单边 · 消息

按「远端内存怎么被访问」从细到粗排成一条谱系：

语义怎么访问远端粒度要不要注册缓存一致代表
load/store 语义（≈ 内存语义互连）用 load/store 指令直接读写地址，像本地内存cache line 级免注册（建页表映射即可）可CXL.mem / NVLink / HCCS
RDMA 单边语义RDMA Read/Write 直接读写远端已注册内存（MR），远端 CPU 不参与消息级（有 read/write 放大）必须先注册 MR、拿 key无InfiniBand / RoCE / GPUDirect
消息语义显式 send/recv，双方按消息收发、匹配消息级视实现无TCP / 传统网络 / IB send-recv
表中几个术语的说明：
  • 粒度 · cache line 级：访问/传输的最小单位是一条「缓存行」（cache line，通常 64 字节，部分 ARM / 加速器为 128 字节）。load/store 语义可以只读/写一个 cache line，只搬你真正碰到的数据，没有「读写放大」，所以延迟低。
  • 粒度 · 消息级：传输的最小单位是一整条「消息」（一个 buffer / 块）。即便你只想动 1 字节，也要按一整块消息来发/收，每条消息还有协议头与队列开销，存在「读写放大」——小访问被放大成整块传输。
  • 缓存一致（Coherence）：多个观察者（CPU 核 / GPU / NPU）各自有 cache、都缓存了同一块内存时，保证「同一个地址的多个副本最终收敛到一致的值」。它只约束「同一地址的副本收敛」，不约束「不同地址之间的顺序」（后者叫一致性模型 Consistency）。
  • 视实现：指「要不要注册」取决于具体是哪种消息语义的实现——RDMA 需要先注册内存（MR）；而 TCP / 传统网络的消息语义不需要注册，由内核协议栈自己管理缓冲区。
术语提醒：「内存语义」有歧义——有时指「直接操作内存实体」（可涵盖 IB 的 RDMA），有时指「load/store 式统一编址」（CXL 口径）。本文统一用后者：内存语义 ≈ load/store 语义，与「消息语义」相对。RDMA 是夹在中间的「单边消息语义」：底层是队列/消息机制，但单边 Read/Write 让它「看起来像直接访问内存」。

1.3 load/store 与 put/get：从原理到代码

这俩都是「读写」，但谁执行、怎么执行、同步还是异步完全不同。一句话：load/store 是「我亲自去拿/放」（处理器指令），put/get 是「我叫搬运工去搬」（通信库 API）。

load / storeput / get（内存级 RMA）put / get（对象级）
是什么处理器指令通信库函数存储引擎函数
操作对象地址（cache line / 字节）buffer / 内存块Key-Value 对象
同步性同步（load 返回即得值）异步（发起后查完成）异步/同步（引擎封装）
谁执行CPU / GPU 自己DMA 引擎 / 网卡引擎（底层再走 DMA）
要不要注册不用（页表映射）要（MR 注册 / 对称堆）引擎自己管
代表CXL.mem / NVLink / HCCSshmem_put/get · hixl_put/get · RDMA WRITE/READMemCache / Mooncake Store

① load/store：处理器指令，地址级，硬件透明

// 统一内存语义（CXL / NVLink / HCCS）：远端地址像本地一样直接 load/store
int *remote = (int *)remote_gva;   // 远端内存的全局虚拟地址
*remote = 42;                      // store：一条 STORE 指令，直接写远端
int v = *remote;                   // load：一条 LOAD 指令，直接读远端
// 硬件负责地址路由 + 缓存一致性，你感觉不到"通信"

② put/get（内存级）：SHMEM / HiXL / RDMA

// SHMEM（PGAS）：显式单边 put/get，异步，要同步
#include <shmem.h>
shmem_init();
int *buf = (int *)shmem_malloc(n * sizeof(int));   // 对称堆
shmem_int_put(buf, src, n, pe);   // put：把 src 远程写到 PE 的 buf
shmem_int_get(dst, buf, n, pe);   // get：从 PE 的 buf 远程读
shmem_barrier_all();              // 同步：确保完成与可见

// HiXL：先注册内存，再单边搬运（异步，查询完成）
hixl_register(engine, buf, len);
hixl_put(engine, remote_addr, buf, len, peer);   // put：搬到远端
hixl_get(engine, buf, remote_addr, len, peer);   // get：从远端拉

// RDMA（IB Verbs）：注册 MR → post WQE(RDMA WRITE) → 轮询 CQ
ibv_reg_mr(pd, buf, len, ...);            // 注册 MR，得 rkey
ibv_post_send(qp, &wr, &bad_wr);          // wr.opcode = IBV_WR_RDMA_WRITE（put）

③ put/get（对象级）：MemCache / Mooncake Store

# 对象级：Key-Value 存取，引擎内部决定走 shmem 还是 hixl
cache.put("req_123", kv_tensor)   # 存对象
kv = cache.get("req_123")         # 取对象
关键洞察：load/store 是「硬件透明」——你写 *ptr = x，硬件自动路由到远端并维护一致性，同步返回，感觉不到通信；put/get 是「显式发起」——你调用 put(dst, src, len)，明确让 DMA/网卡搬这批数据，异步完成。所以 load/store 是「内存语义」，put/get 是「消息/通信语义」。一个易混点：SHMEM 的 shmem_put 虽然叫 put，但它是「显式远程写 + 要同步」，不是 CXL 那种「透明、同步、硬件一致」的 load/store。
图：load/store（内存语义）的硬件时序——注意它没有 MR 注册、没有 QP/doorbell/CQ、同步返回，全程硬件透明；对比 §4 Step 4 的 RDMA（消息语义）时序图（异步、显式、要注册）。

1.4 缓存一致 vs 一致性模型

缓存一致（Coherence）：多个观察者（CPU 核 / GPU / NPU）各自有 cache，都缓存了同一块内存时，保证「同一个地址的多个副本最终收敛到一致的值」。它只回答「同一地址的副本怎么收敛」。 一致性模型（Consistency）：规定「不同地址之间读写操作的顺序与可见性」。

两个关键不等式（贯穿全文）：Coherence ≠ Consistency（缓存一致 ≠ 跨地址强一致）；Completion ≠ Visibility（提交返回 / 本地完成 ≠ 远端已能安全消费）。所以单边通信里常要额外用 fence/barrier 建立「先放货、后翻 ready 标志」的顺序。

2.1 执行层的双引擎：shmem vs hixl

这是昇腾执行层里最容易被混淆的两个库。先记住一句话：shmem 是「内存池」，hixl 是「快递员」。

维度shmem（共享内存库）hixl（单边通信库）
定位把多卡 HBM 抽象成「一块全局内存」面向集群的单边数据传输
编程模型PGAS（分区全局地址空间），OpenSHMEM 兼容单边通信（One-Sided）
出发点「访问哪个 PE 的哪个地址」「把哪段数据从 A 搬到 B」

关系（关键，避免误解）：shmem 和 hixl 是并列的两个引擎，不是「谁构建于谁之上」；两者都基于单边通信 + 零拷贝，共同建立在基础设施层 MemFabric 的统一编址（GVA）之上。工程上的典型分工是节点内细粒度用 shmem、跨节点大块用 hixl。

Step 1 · Prefill 计算，产出 KV Cache
这一步干什么：Prefill 实例跑前向，注意力层输出 Key/Value。KV 大小 ≈ 层数 × KV 头数 × 头维 × 序列长度 × 2(K/V) × 精度。

这一步是「计算」而非「通信」，但它是后续所有搬运的货的源头。PD 分离的价值在于：Prefill 是算力密集，Decode 是访存密集，拆到不同硬件上各用最合适的机器。

Step 3 · 选择通信语义
这一步干什么：把「搬运 KV / 梯度 / 专家 token」表达成某一种通信语义。语义分三大类 + 一个 MoE 专用。
语义代表出发点（一句话）对端参与何时选它
集合通信NCCL / HCCL整组完成哪个 collective（AllReduce/AllGather/AllToAll）双边（全组参与）数据并行梯度 AllReduce、张量/流水线并行
单边 buffer 传输TransferEngine / HiXL哪批 buffer 从 A 搬到 B单边（对端不参与）PD 分离 KV 搬运、RL 权重 P2P、参数服务器推送
PGAS RMANVSHMEM / cann/shmem访问哪个 PE 的哪个地址单边多卡共享参数、MoE 专家通信、算子内协同
MoE all-to-allDeepEPMoE 的 dispatch / combine双边（EP 组）MoE/EP 训练与推理

单边 buffer vs PGAS：更清晰的区分

最本质的一句话：单边 buffer 是「搬一整箱货」（一次性大块搬迁）；PGAS 是「共享货架，随时伸手拿任意格子」（持续的全局地址空间 + 细粒度/原子访问）。
维度单边 buffer（TransferEngine/HiXL）PGAS（SHMEM/NVSHMEM）
数据单位一批连续 buffer（大块）一个可寻址地址（可细到 cache line/一个变量）
全局地址空间没有；每次显式给 src/dst+长度有（对称堆，PE号+偏移），一次建立长期复用
访问模式块级「搬」一次就结束反复 put/get + 原子（AMO）+ fence/barrier
原子/锁一般不做能（atomic add/swap、搭锁）
语义本质更像「传输/消息」（memcpy/快递）更像「内存/load-store」（共享内存）
判断口诀：「我要一次性把一整块送过去」→ 单边 buffer；「我要建立一个能反复、随机、细粒度读写的共享地址空间，甚至要原子操作」→ PGAS。
关键澄清：三者是并列的编程模型，不是谁包含谁。SHMEM 能自己拼出 collective，但不能说它包含 NCCL。DeepEP 本质是「为 MoE 优化的 all-to-all」——落在「集合通信」与「单边传输」之间的专用点，针对 MoE 的稀疏、不均衡做了专用优化，比通用 NCCL AllToAll 更合适。
Step 4 · 建立地址与内存注册
这一步干什么：让发起方能「命名」并「访问」远端内存。不同语义对「地址怎么建立」的要求不同。
机制生态干什么
内存注册 MR英伟达 / RDMA 通用把参与传输的内存 pin 住并登记，拿到 key，配 QP/CQ，远端才能写
VMM昇腾Reserve / Physical / Map / SetAccess，管理 VA、物理页、权限
IPC昇腾导出/打开「设备内存句柄」，让另一进程看见同一块 NPU 内存
对称堆SHMEM 系每个 PE 分配同样大小/布局的内存，地址对称，才能用「PE 号 + 偏移」寻址
Fabric Memory昇腾把远端物理内存映射进本地地址空间（统一编址模式）
CXL load/store通用用 load/store 语义直接访问，无需显式注册
消息语义 vs 内存语义「注册」的最大区别：消息语义（RDMA）必须先注册内存（pin + 拿 key）、再建 QP/CQ，远端凭 key 才能写——控制面重；内存语义（CXL）通过地址映射（页表/MMU）直接建立可访问地址，之后 load/store 直接访问——免注册、免 key、免队列，控制面轻。

WQEWork Queue Element（工作队列元素）一次请求：SEND / RDMA WRITE / RDMA READ
CQCompletion Queue（完成队列）完成通知的 FIFO 队列
CQECompletion Queue Entry（完成元素）一条「已完成」记录，应用轮询它

Step 5 · 提交任务与异步重叠
这一步干什么：决定「谁把搬运任务提交给硬件」，以及「搬运能不能和计算重叠」。
方式谁提交特点
Host 提交Host CPU 逐项下发（TS 调度器）简单，但每步要 CPU 参与，控制路径长
AIV 直驱（昇腾）Device 侧 Vector Core把细粒度任务提交下沉到设备侧，CPU 不逐项指挥
GPU-initiated / 异步（英伟达）GPU 侧（GDR / async copy）NCCL 通信-计算重叠、DeepEP 低延迟异步 dispatch

同步骤区别：核心是「控制路径」的归属——由 CPU 逐步指挥，还是由设备侧直驱。异步 + 重叠（overlap）是隐藏通信延迟的关键：算第 N 层的同时，第 N-1 层的数据在后台搬。

Step 6 · 搬运数据与物理链路
这一步干什么：真正把字节搬过去。分两件事：谁搬（搬运引擎）+ 走哪条路（物理链路）。

Step 7 · 完成、一致性与可见性
这一步干什么：确认「数据真的搬完、对端真的能安全读」。这是最容易被忽略、也最容易出错的最后一步。
  • 完成通知：RDMA 的 CQ/CQE、DMA 的完成记录、SHMEM 的 quiet/fence。
  • 同步原语：barrier、put-with-signal、原子操作 + fence，建立「先放货、后翻 ready 标志」的发布-消费关系。
两个关键不等式：Completion ≠ Visibility（本地完成 ≠ 远端能安全消费）；Coherence ≠ Consistency（缓存一致 ≠ 跨地址强一致）。
