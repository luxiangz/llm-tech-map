大语言模型后训练技术体系深度调研 · 第 8 章

实验证据与计算成本：横向比较的事实基础

本章结论：所有可靠的成本数字都指向同一方向——监督/蒸馏类方法比在线 RL 便宜一到两个数量级：Qwen3 官方对照（同起点 8B）：on-policy 蒸馏 1,800 GPU 时 > RL 17,920 GPU 时（AIME'24 74.4 vs 67.6）；Tulu 3：PPO≈7–14× DPO 成本；TM 博客：OPD 对齐同水平省 9× FLOPs / 18× GPU 时，学习 RL 策略省 50–100×。系统侧：RLHF 迭代时间中 rollout 生成可占 81.2%（NeMo-Aligner 基线），因此 colocate/分离架构与生成引擎优化是 RL 工程的主战场。方法侧的资源结构差异必须先看清：PPO 驻留 4 个大模型、GRPO 3 个、OPD 2 个（学生+教师，教师只前向）、DPO 2 个（学生+参考）、SFT 1 个。性能结论则必须带条件引用——同一方法在小模型与大模型、可验证与不可验证任务上的排序可以完全反转（R1：小模型蒸馏>直接 RL；边界推进需大模型+大规模 RL）。

8.2.2 系统与基础设施

  • HybridFlow/veRL [2409.19256]（EuroSys 2025）：NeMo-Aligner 基线中生成占 RLHF 迭代时间 81.2%（缺 KVCache）；3D-HybridEngine 让训练/生成共置切换并行度；16–64 GPU 全 colocate 最优，96+ 分离更优；较 DeepSpeed-Chat/OpenRLHF/NeMo-Aligner 吞吐 1.53–20.57×。A
  • Apple 蒸馏缩放律 [2502.08606]（off-policy 蒸馏）：学生 CE = 教师 CE + 学生模仿能力项；教师不是越强越好（capacity gap 是相对学习能力的差距，教师过强反而降低学生表现）；"教师现成或多学生"时蒸馏胜监督学习，"单学生且须自训教师"时监督学习通常更优；算力分配随学生规模变化（小学生小预算→大头给教师预训练）。A
  • RL 具体卡时：R1 论文未披露总 GPU 时（附录 B.4.4 未公开数字，标注未核实）；Tulu 3 SFT 8B=32 GPU×6h、70B=64 GPU×50h；DAPO 512 prompt×16 rollout/步。A（数字）/未披露处如实标注

共性规律：2024 年后的所有配方都是"SFT/蒸馏先行 → 偏好或 RL 锐化 → 迭代中重置数据分布"；纯 RL（R1-Zero）只在最大规模 base 上可行；小模型一律退回蒸馏主导。A（多系统一致）

8.4 可验证域之外：为什么通用域退回偏好优化

  • 写作/对话等任务没有程序化 verifier，只能用可被利用的学习式 RM——Secrets Part I 的 pattern collapse、InstructGPT 的 KL 必要性、R1 阶段④ RM 后置（1,700 步中最后 400 步）都源于此。
  • Tulu 3 的 IFEval 路线说明部分"软"指令可半形式化为可验证约束（约束校验函数做 verifier），但覆盖面有限。
  • Agent/环境交互任务（Kimi K2 的 joint RL）以环境反馈（测试通过、任务成功）为奖励，是 RLVR 的自然扩展；多轮信用分配仍未解决（SDPO/隐式 PRM 在向此延伸）。

8.5 引用性能数字的检查清单

  1. 模型规模与基座（同一方法在 1.5B 与 32B 上排序可能反转）；
  2. 起点（从 base 还是从 SFT/蒸馏 checkpoint 起——Qwen3 Table 21 三分支同起点才可比）；
  3. 基准与指标（pass@1 vs avg@k vs pass@64——RL 与蒸馏对三者的作用方向可以不同）；
  4. 训练预算（GPU 时/步数/token 数——无预算数字的性能比较意义有限）；
  5. 评测温度与采样策略（pass@k 对温度敏感，Yue et al. 用 T=0.6/top-p 0.95）；
  6. 对照是否同期训练（"蒸馏 vs RL"结论几乎都来自教师极强的不对称设置）。
