01 动机：LLM 推理的带宽瓶颈

WHY — AUTOREGRESSIVE DECODING IS MEMORY-BOUND

大语言模型生成文本的过程是自回归（autoregressive）的：每生成一个 token，就要把整个模型的所有参数从显存读一遍。当模型足够大时，真正卡住速度的不是计算，而是显存带宽（memory bandwidth）。

1.1 一个算数问题：为什么大模型生成这么慢

以 70B 参数的模型为例（FP16 存储）：

权重大小 ≈ 70 × 109 × 2 字节 ≈ 140 GB

在 NVIDIA H100（显存带宽约 3.35 TB/s）上，每生成一个 token 至少要读一遍全部权重：

单 token 理论下限 ≈ 140 GB ÷ 3.35 TB/s ≈ 42 ms → 约 24 tok/s

在 A100 80G（约 2 TB/s）上则只有约 14 tok/s。而一次前向中每个 token 的激活量（激活、KV cache 增量）不过几百 KB 到几 MB —— 相比 140 GB 的权重读取可以忽略不计。这就是关键洞察的起点：

💡 核心洞察 既然瓶颈是"把权重读一遍"，那么一次前向里塞进 1 个 token 还是 K 个 token，耗时几乎一样（K 个 token 的额外计算和额外显存读取都很小）。自回归解码"一次只验证一个 token"，把带宽利用率拉到了极低 —— 这就是投机解码要补的洞。

1.2 从"串行猜测"到"批量验证"

传统自回归解码的工作方式是：

  • 用已生成的 <prefix> 跑一次前向 → 得到下一个 token 的分布 → 采样出 x₁；
  • 再把 <prefix, x₁> 跑一次前向 → 得到 x₂；
  • 如此循环 —— 每一步都完整读取一遍全部权重，且每一步之间严格串行。

投机解码（speculative decoding）的思路则完全相反：先让一个又快又小的"草稿模型"连续猜出一整串候选 token，然后让大模型用一次并行前向把它们全部验证掉。被验证通过的 token 全部免费"预支"到手，被拒绝的 token 用数学上严格的方法修正 —— 整体分布与大模型直接解码完全一致。

ℹ️ 什么时候有效，什么时候无效 投机解码针对的是单请求、小 batch、内存带宽受限的延迟场景（如交互式聊天、单流推理）。当 batch 很大时，权重读取被多个请求摊薄，推理转为计算受限，投机解码的收益会明显下降；在并发批处理（continuous batching）下收益也会被压缩。这也是为什么生产环境实测加速通常落在 2–4×，而不是论文里的理论值。

1.3 MoE 模型不用读完全部权重：激活参数的带宽账本

上面的 140 GB 例子对稠密模型成立——每个 token 都要读全部权重。但近年主流模型大量采用混合专家（MoE）结构（DeepSeek-V3/V4、Qwen3-30B-A3B、GLM-5.2、Kimi K3、Mixtral 等），其带宽账本完全不同，关键在于总参数 vs 激活参数的区别：

  • Mixtral 8×7B：专家部分 = 176M（每专家 FFN：4096×14336×3）× 8 专家 × 32 层 ≈ 45.1B；共享层（attention / embedding / router）≈ 1.6B；总 46.7B ✓。激活 = 1.6 + 45.1×2/8 ≈ 12.9B ≈ 13B ✓。注意 "7B" 是近似命名，单个专家 FFN 实际仅 ~0.18B；

  • Qwen3-30B-A3B：专家部分 = 4.7M（2048×768×3）× 128 专家 × 48 层 ≈ 29.0B；共享层（含 embedding 与 lm_head）≈ 1.5B；总 30.5B ✓。激活 = 1.5 + 29.0×8/128 ≈ 3.3B ✓（官方 3.35B，完全对上）；
  • DeepSeek-V4-Flash：路由专家部分 = 25M（4096×2048×3）× 256 专家 × 43 层 ≈ 277B + 共享专家 ≈ 1.1B；共享层（CSA/HCA 注意力、embedding）≈ 6B；总 284B ✓。激活 = 6 + 1.1 + 277×6/256 ≈ 13.6B ≈ 13B ✓；
  • GLM-5.2：路由专家部分 ≈ 727B（78 层 × 256 专家）；共享层（MLA 注意力、DSA indexer、embedding）≈ 17B；总 744B ✓。激活 = 17 + 727×8/256 ≈ 39.7B ≈ 40B ✓；
  • Kimi K3：路由专家部分（Stable LatentMoE）≈ 2.74T；2 个共享专家 + 稠密层（KDA/MLA、embedding）合计 ≈ 55B；总 2.8T ✓。激活 = 55 + 2.74T×16/896 ≈ 103.9B ≈ 104B ✓（宣称稀疏度 1.8% 与专家激活比例 16/896 = 1.79% 吻合）。

四个要点：

  • ① 专家激活比例 < 激活参数占比：专家激活比例（Mixtral 2/8、Qwen3 8/128、DeepSeek 8/256、V4-Flash 6/256、GLM-5.2 8/256、K3 16/896）都低于各自的激活参数占比（27.6%、10.8%、5.5%、4.6%、5.4%、3.7%）——共享层每 token 全读，把占比"垫高"了；
  • ② 外推前先扣共享层：若用"激活参数 ÷ 激活专家数 × 总专家数"外推总参数，必须先扣除共享层，否则会高估（Mixtral 13/2×8 = 52B > 47B 就是这么来的）；
  • ③ 架构细节决定账本：是否有共享专家（DeepSeek 有）、MoE 层占比（DeepSeek 58/61、Qwen3 与 V4-Flash 全部层都是 MoE）——用公式前先查 config；
  • ④ DeepSeek-V4-Pro 待验证：V4-Pro（1.6T / 49B）专家数尚未公开，暂无法套用公式验证——发布后按同样流程分解即可。
  • 每 token 读取量 = 共享稠密层（embedding、注意力、router，全读）＋ 被路由激活的 k 个专家（k 通常 2–8）。以 DeepSeek-V3 为例：约 37 GB ÷ 3.35 TB/s ≈ 11 ms → ~90 tok/s 量级——比同总参数的稠密模型高一个数量级；
  • 显存仍须全部驻留：671B 权重依然要完整加载（或部分 offload），被压缩的只是读取带宽——路由机制让你"不用搬"，但必须"装着"。原因有二：
    • ① 路由动态性：路由由当前 token 的 hidden state 动态决定、逐 token 变化——无法预知下一个 token 激活哪些专家，任何专家都必须随时可用；
    • ② 换入成本：若按需从磁盘/CPU 换入专家，PCIe 带宽（~64 GB/s）比显存带宽（~3.35 TB/s）慢约 50 倍——换入一个专家（~2.4 GB）就要 ~37 ms，比 GPU 直接读完全部激活权重（~11 ms）还慢，按需加载反而毁掉 MoE 唯一的带宽优势。工程折中（如 llama.cpp 的专家级 offload）只对低频专家生效，且一旦路由到被 offload 的专家就会产生延迟尖峰。
  • 共享层仍全读：注意力层（如 DeepSeek-V3 的 MLA）是稠密的，每个 token 都要读；
  • 瓶颈转移：多卡部署时专家分散在多张卡上，每 token 的 all-to-all 通信成为新瓶颈——MoE 解码的瓶颈从"权重带宽"转向"通信带宽"。这也决定了 MoE 的多卡并行要用大 EP（专家并行，Expert Parallelism）：EP=N 表示把全部专家均分到 N 张卡（每卡 专家总数/N 个），token 经 router 激活的专家若在别的卡上，就经 all-to-all 通信 dispatch 过去计算、再 combine 回来。

    EP 与 TP 的分工：两者是正交的两个维度、生产中总是配合使用——TP 切分稠密层（attention 的 QKV/O、embedding：矩阵切成多份、每步 all-reduce 同步），EP 切分稀疏层（专家 FFN：每卡只算自己被激活的专家）。专家层不能用 TP 代替 EP：总 FLOPs 无论怎么切都不变（都是 8 个激活专家），但 TP 切专家会改变计算图的连接结构——EP 下 token 只与激活专家所在的 8 张卡通信（稀疏连接，其余卡可同时处理别的 token），TP 下每个激活专家都切分在全部参与卡上，token 必须流经每一张卡、每算一个专家就 all-reduce 同步一次，专家级并行退化为矩阵级并行、卡间强同步（SIMD）——这就是"稀疏计算被稠密化"的含义：省的不只是"算多少"，更是"token 只和少数卡发生关系"。因此生产配置是"大 EP + 小 TP"。

    EP 必须大的原因有三：

    • ① 显存：专家总参物理上装不进单卡——DeepSeek-V3 专家部分 653B fp8 ≈ 653GB，EP=8 时每卡 82GB 已超 H100 80GB，EP=64 时每卡仅 ~10GB；
    • ② 负载均衡：decode 时每 token 只激活 8 个专家——EP 大（如 64，每卡 4 个）时这 8 个专家分散在 8 张卡上并行计算；EP 小（如 8，每卡 32 个）时可能全挤在 1–2 张卡上造成热点过载、其余卡空闲。batch 内大量 token 的专家计算靠大数定律在卡间趋于均匀，卡越多越均衡；
    • ③ 延迟：专家计算并行度 = 激活专家分布的卡数，EP=64 时单 token 延迟降到"单专家计算"量级。

    但 EP 不能无限大：EP 上限是专家总数、必须整除；attention 权重不随 EP 切分（由 TP/PP 负责），EP 增大的同时 attention 权重要在每张参与卡上驻留或跨卡同步，卡越多这部分开销越大；all-to-all 通信量随 EP 增大（token 要与更多卡通信），受 NVLink/NVSwitch 互联带宽约束。DeepSeek-V3 官方训练用 EP=64（每卡 4 专家）+ TP，vLLM/SGLang 社区推理常用 EP=32/64 + TP=1~8；Kimi K3（896 专家、2.8T）则需要大 EP + 多节点（64+ 加速器）才能部署。

这对投机解码有两个直接影响：一是 MoE 目标的单 token 成本更低，投机收益需重新实测（附录 A.1 的 DFlash 实验正是基于 MoE 的 Qwen3-30B-A3B）；二是草稿头（EAGLE / MTP）通常只挂 MoE 的共享层，草稿开销进一步降低——两者同向有利。

02 核心原理：草稿与验证

DRAFT THEN VERIFY — THE SPECULATIVE DECODING LOOP

2.1 两个角色

角色草稿模型（Draft Model）目标模型（Target / Verifier）
职责 快速猜出后续 K 个候选 token（投机长度 K，也叫 γ） 一次并行前向，校验全部候选，并产出修正后的 token
规模 远小于目标模型（如 0.3–2B vs 8–70B），或仅是一个额外的"解码头" 用户真正想要的那个大模型
来源 独立小模型 / 目标模型的子模块 / 特征层外推头 / n-gram 匹配（无参数） 任意现成 LLM
分布 q(x) —— 可能与大模型不一致，允许犯错 p(x) —— 最终输出必须严格服从它

2.2 一轮完整的草稿—验证循环

  • ① 草稿（Draft）：草稿模型基于当前前缀（含 KV cache），自回归地（或用并行方法）生成 K 个候选 token d₁ d₂ … d_K；
  • ② 拼接（Extend）：把候选串接到前缀后面，目标模型只跑一次前向，同时得到每个位置上的真实分布 p(·|prefix, d₁…d_{i-1})；
  • ③ 验证（Verify）：从左到右逐个位置做拒绝采样检验：草稿 token 是否与大模型分布一致？
  • ④ 接受 / 修正（Accept / Resample）：接受连续被验证通过的 token；遇到第一个不一致的位置，从残差分布重采样一个 token 替换它；
  • ⑤ 更新（Update）：把被接受的 token（以及重采样出的那个 token）写入 KV cache，进入下一轮。
💡 三个直觉
  • 草稿允许犯错：候选被拒不损失正确性，只是浪费了草稿阶段的算力；
  • 验证永远免费并行：K 个候选的验证只花一次目标模型前向的时间；
  • 一轮保底前进 1 个 token：哪怕全部候选都被拒，重采样也必然产生一个合法 token —— 所以投机解码的最差情况也只是"多花一次小模型前向"，而不是退化。

2.3 为什么一次前向能同时验证多个位置：因果掩码的"免费午餐"

"一次前向同时算出所有候选位置的目标分布"不是投机解码发明的技巧，而是因果语言模型的天然属性。用具体例子看：设前缀长度 L、草稿生成 3 个候选 d₁ d₂ d₃，目标模型输入序列 [x₁…x_L, d₁, d₂, d₃]（长度 L+3），标准的下三角因果掩码保证：

输入位置因果掩码可见范围输出分布验证用途
L（真实前缀末位）[1..L]p₀ = p(·|x₁…x_L)验证草稿 d₁
L+1（草稿 d₁）[1..L+1]p₁ = p(·|x₁…x_L, d₁)验证草稿 d₂
L+2（草稿 d₂）[1..L+2]p₂ = p(·|x₁…x_L, d₁, d₂)验证草稿 d₃
L+3（草稿 d₃）[1..L+3]p₃ = p(·|x₁…x_L, d₁, d₂, d₃)若全部接受，直接作为下一轮起点

每个位置都在预测"下一个 token"，而因果掩码保证位置 i 的输出只看到前 i 个 token——所以拼接候选后的一次前向，天然等于同时做了多个位置的预测，验证所需的全部目标分布一次拿全。这就是"一次前向验证 K 个候选"的机制根基（来源：糖嘟嘟的AI学习笔记《投机解码深度技术解析》）。

2.4 扩散模型（DiT）也有投机解码：范式不变，验证对象变了

既然投机解码依赖"一次前向算出多个位置的目标分布"，那逐像素去噪的扩散模型（DiT）是不是没有投机解码？答案分两层：

  • 经典 token 级投机解码确实不适用：扩散生成是全局连续的迭代去噪（x_T → x₀，通常 20–50 步），没有"词表分布"，也没有"一次前向验证一串候选 token"的结构——逐位置拒绝采样与接受率分析不直接成立；
  • 但"草稿-验证"范式在扩散领域以改头换面的形式存在且很活跃：草稿从"猜 token 串"变成"预测未来的去噪步骤结果"（轻量 Taylor 外推 / 特征缓存 / 自投机），验证从"比对逐位置分布"变成"重算检查状态一致性"（L² 误差 / 端点对齐）。

03 数学基础：拒绝采样与无损保证

REJECTION SAMPLING — THE LOSSLESS GUARANTEE

投机解码最迷人的地方在于：它不是一个启发式近似，而是一个数学上无损（lossless）的采样过程。输出分布与目标模型直接解码逐 token 完全一致。这一保证来自经典的拒绝采样（rejection sampling）技术，最早由 Leviathan 等（2023）与 Chen 等（2023）独立给出。

3.1 先搞清楚问题：我们想要的，和我们有的

投机解码的"无损"不是一个玄学口号，而是一个可以严格证明的等式。为了看懂它，先把局面摆清楚：

  • 目标分布 p(x)：目标模型在给定前缀下对下一个 token 的真实概率分布。这是质量红线——最终输出的每一个 token，都必须严格服从 p，不允许近似、不允许打折；
  • 草稿分布 q(x)：草稿模型的分布。它便宜、快，但 q ≠ p（草稿会"猜错"）；
  • 手里的牌：草稿已经替我们按 q 采出了一个候选 token x。我们不能重新采样（那等于直接跑目标模型，没有加速了），只能对已有的 x 做"接受 / 拒绝 / 修正"。

补充：p(x) 与 q(x) 的具体形态——它们是词表大小 |V| 的一维概率向量（如 Llama 32k、Qwen3 151k、DeepSeek 128k），每个元素 p(vᵢ) 是"给定前缀下下一个 token 恰好是词表中第 i 个 token"的概率：

  • 形状：单请求解码时实现为 [1, |V|]（batch=1）；投机解码"一次前向多位置"（§2.3）时为 [seq_len, |V|]——每个位置一行，各是一个独立的分布；
  • 产生链路：hidden state h_t → LM Head 线性层 → logits z（[|V|]，未归一化的分数）→ softmax → p。softmax 保证 p(vᵢ) ≥ 0 且 Σᵢ p(vᵢ) = 1——这是 §3.3 六步证明中 Σ_x p(x) = 1、α = Σmin(q,p) 能算的前提；
  • 下标取值：接受概率 min(1, p(x)/q(x)) 里的 p(x) 就是 p[x]——取草稿采中的那个 token 在分布中的概率（一个标量），q(x) 同理；拒绝后的残差重采样也是在完整的 [|V|] 上构造 r ∝ max(0, p−q) 再归一化（呼应 §3.2"重采样是词表级"）；
  • 每个"下一步"都重新算：p 是"给定当前前缀下下一个 token"的条件分布，每前进一个 token 都要基于新前缀重算——投机解码"一次前向多位置"正是把多个这样的分布一次拿全；
  • 采样修饰发生在 softmax 前后：温度在 softmax 前缩放 logits（§3.8），top-k / top-p 在 softmax 后截断并重新归一化（截断后和不再是 1）——但最终交给拒绝采样的 p 始终是合法的概率分布。

于是问题变成：如何设计一个"裁判"，把 q 采出的样本 x，改造成一个服从 p 的样本？要求有两个：

  • ① 正确性：改造后的输出分布必须严格等于 p；
  • ② 效率：大多数时候能直接接受（白拿草稿的成果），只在必要时才额外花算力修正。

3.2 裁判的两条规则

规则 1（接受）：采样 u ~ U[0,1]，若 u ≤ min(1, p(x) / q(x))，接受草稿 token x式 (1)
规则 2（拒绝）：从残差分布重采样：　r(x') ∝ max(0, p(x') − q(x'))式 (2)

规则 2 为什么长这样：三个设计要求逐条翻译。这个表达式不是随意写的，而是"拒绝后如何补抽"的三个要求逐条翻译的结果：

  • ① 要求一：拒绝后从整个词表重新抽——拒绝后当前位置需要一个新 token，它来自定义在整个词表上的合法概率分布（不是围绕被拒 token 转，呼应下面图 3c 的"分水岭"）。→ 表达式用 ∝（正比于）：表示"归一化后才是分布"；
  • ② 要求二：只能补"草稿给少了"的 token——补抽的预算来自"给多了的 token 被拒时腾出的份额"（概率守恒），补到不缺的 token 上是白补。→ max(0, ·) 把差额为负（草稿给多了）和为零（刚好够）的位置全部截断归零；
  • ③ 要求三：缺多少补多少——无损红线要求输出频率恰好 = p：接受路已贡献 min(q,p)，剩余部分 p − min(q,p) = max(0, p−q) 必须由拒绝路原样补上。→ 补抽概率正比于缺口大小 p(x') − q(x')（缺口 0.2 的 token 被补抽的概率是缺口 0.1 的两倍）。

三个符号各管一个约束：∝ 保证它是分布，max(0,·) 保证只补缺口，p−q 保证补得精确。而且这个表达式是被无损条件唯一决定的：输出 = min(q,p) + (1−α)·r 必须等于 p，解出 r = max(0, p−q)/(1−α)（式 6）——换成任何别的分布都会"有损"。含义一句话：规则 2 是一份"缺口清单"采样器——缺口越大的 token 越可能被补抽，没有缺口的（含给多了的）绝不补抽。

把 min(1, p/q) 想成一个"概率折扣器"——把草稿的采样频率打折到目标模型认可的额度：

  • p(x) ≥ q(x)（目标比草稿更看好 x，含 p/q > 1 的严格情况）：min(1, p/q) = 1 → 无条件接受。注意接受概率被钳制在 1——它是概率，不能超过 1；而且此时草稿"给少了"（q(x) < p(x)），全收都还不够目标要的份额，缺口 p(x) − q(x) 由规则 2 的补抽补齐（见 §3.4 中 B 行的完整账目）；
  • p(x) < q(x)（草稿过度自信）：以概率 p/q 接受（打个折扣），否则进入规则 2——从两种分布的差集里补抽，把草稿漏掉的目标概率找回来。

一句话记住 min(1, p/q) 的哲学：只裁掉草稿的"过度自信"（q > p 时打折），从不裁草稿的"谦逊"（q < p 时全收，缺口由拒绝路补）。所以接受路最多贡献 min(q, p)，永远不可能超过草稿实际采到的份额。

注意规则 2 的重采样不依赖刚被拒绝的那个 x，而是看整个分布的差额——"哪些 token 是目标模型比草稿模型更看好的"。被拒绝只是触发了"盘点差额"这件事。

🧮 深入理解：为什么必须用随机数 r，而不是固定阈值？ 有人会问：既然接受概率是 min(1, p/q)，为什么不设个固定阈值（比如 p/q > 0.5 才接受），省掉随机数？答案是：固定阈值会系统性扭曲输出分布。举例：目标模型认为 token A 应有 10% 的概率出现，草稿模型却高估到 90%——此时 p/q = 1/9 ≈ 0.11 < 0.5，固定阈值会永远拒绝 A，A 的实际出现概率被压到 0%，而不是正确的 10%。而随机数机制下，A 仍有 1/9 的概率被"侥幸"放行，长期统计恰好还原 10%。随机性不是工程的妥协，而是精确还原分布 p 的数学保证（呼应 §3.5 误区 2；来源：糖嘟嘟的AI学习笔记）。
💡 "长期统计恰好还原 10%"的原理 核心就一个等式：接受频率 = 草稿频率 × 折扣率 = q × (p/q) = p——乘法里 q 被精确消掉了。草稿再怎么高估（q 再大），折扣率 p/q 就相应变小，两者相乘永远回到 p：
"采到 A 且被接受"的频率 = q(A) × min(1, p(A)/q(A)) = 0.9 × 1/9 = 0.1 = p(A)式 (3)

"长期"的数学依据是大数定律：每次接受/拒绝是独立的伯努利试验，次数足够多时频率收敛到期望——草稿采样 1000 次，约 900 次采到 A，其中每次以 1/9 概率放行，900 × 1/9 ≈ 100 次接受 → A 出现约 10%。且 A 不会通过拒绝路再出现（残差质量 max(0, p−q) = 0，因 p < q），所以总频率 = 接受路 0.1 + 拒绝路 0 = 恰好 10%。

对比固定阈值：折扣率要么 0 要么 1，无法完成"q 到 p 的转换"（1/9 < 0.5 → 永远拒绝 → 0.9×0 = 0 ≠ 0.1）；随机数机制下"侥幸放行"是精确设计的概率——每次放行的概率恰好是 p/q。这也就是 §3.3 式 (5) 的实例：P(接受且输出 A) = q·min(1, p/q) = min(q,p) = 0.1，每一次试验的期望贡献就是 0.1，大数定律保证频率收敛到它。

3.3 无损保证：六步证明

下面把"输出分布 = p"完整推一遍。每一步都写清理由，一共只需要六步：

第 1 步：把"最终输出 x"拆成两条互斥路径

P(输出 x) = P(接受且输出 x) + P(拒绝后重采样到 x)式 (4)

一个 token 要么走"接受"路直接输出，要么走"拒绝 → 重采样"路输出。两条路互斥（接受和拒绝不会同时发生），所以总概率等于两者之和。

第 2 步：算"接受且输出 x"的概率

P(接受且输出 x) = q(x) × min(1, p(x)/q(x)) = min(q(x), p(x))式 (5)

草稿先以概率 q(x) 采出 x，裁判再以概率 min(1, p/q) 放行。乘起来后化简：若 p ≥ q，则 q × 1 = q = min(q,p)；若 p < q，则 q × p/q = p = min(q,p)。两种情况都得到 min(q,p)。

第 3 步：算总接受概率 α

α = Σx min(q(x), p(x))，　总拒绝概率 = 1 − α式 (6)

把第 2 步对所有可能的 token 求和，得到"草稿被放行"的总概率。α 越大，草稿越合格——但注意：α 只决定效率，不决定正确性（正确性由第 6 步保证，与 α 无关）。

第 4 步：给残差分布 r 归一化

r(x) = max(0, p(x) − q(x)) / (1 − α)式 (7)

先验证分母合法：Σx max(0, p−q) = Σx (p(x) − min(p(x), q(x))) = 1 − α。分子分母都是合法量，所以 r 是一个真正的概率分布（非负且和为 1）。

第 5 步：算"拒绝后重采样到 x"的概率

P(拒绝后采样到 x) = (1 − α) × r(x) = max(0, p(x) − q(x))式 (8)

拒绝概率 (1−α) 乘以 r(x)，恰好把归一化因子消掉——结果正是"目标与草稿的差额"。这一步说明重采样不是随便补一个 token，而是精确地补在草稿"给少了"的地方。

第 6 步：合并两路，见证等式

P(输出 x) = min(q(x), p(x)) + max(0, p(x) − q(x)) = p(x)　∎式 (9)

最后一步用到一个对任意两个数都成立的恒等式：min(q,p) + max(0, p−q) = p。分两种情况验证：p ≥ q 时左边 = q + (p−q) = p；p < q 时左边 = p + 0 = p。无论草稿多不靠谱，两条路拼起来都恰好还原完整的 p——这就是"无损"的全部秘密。

💡 一句话读懂证明 接受路补"草稿不自信的部分"（min(q,p)），拒绝路补"草稿过于自信而漏掉的部分"（max(0, p−q)），两路拼起来 = 完整的 p。拒绝采样最优雅的地方在于：纠错代价被压到了最低——只有 q 与 p 不一致的 token 才需要额外的重采样计算，其余全部白拿。

3.5 五个常见误区

  • 误区 1："无损 = 每次生成的文本都一样"。不是。随机采样时每次输出本来就不同；"无损"指的是统计分布相同——投机解码产出的文本流，与目标模型直接解码产出的文本流，在分布上不可区分。只有在贪心（T=0）模式下，两者才逐 token 完全相同；
  • 误区 2："接受率越高越好，干脆全接受"。不能。全部接受 = 输出服从 q（草稿的分布），除非 q ≡ p 否则就"有损"了。拒绝采样正是用"折扣接受 + 差额补抽"这套机制，在严格保住 p 的前提下最大化接受率——接受率是效率指标，无损是正确性指标，两者由式 (1)(2) 统一保证；
  • 误区 3："被拒绝的草稿 token 浪费了"。没有浪费。拒绝触发重采样，补抽出的 token 依然会输出——每轮验证至少前进 1 个 token，最差情况也只是多花一次小草稿的前向；
  • 误区 4："拒绝采样会降低生成质量 / 多样性"。不会。它精确还原 p 的多样性——p 里概率小的 token 依然以同样的小概率出现，质量与直接跑目标模型完全一致；
  • 误区 5："Medusa 的 typical acceptance 也是无损的"。不是。它用温度阈值放宽接受条件来换取更高接受率，是有意偏离严格无损的工程取舍——大多数场景损失可忽略，但性质上已不是"精确保持"。凡是强调 lossless 的场合（如评测对比），应使用标准拒绝采样。

3.6 "无损"的准确含义、验证方法与生产意义

（1）精确定义

对任意前缀与任意生成长度：P_speculative(完整输出序列) = P_vanilla(完整输出序列)式 (10)

即：投机解码产出的整个序列的联合分布，与目标模型自回归解码完全一致。逐 token 成立后，序列层面由链式法则自然成立——但"从左到右"这个顺序不是惯例，而是硬约束：

  • 语言模型建模的是条件分布 p(x_t | x<t)：第 3 个 token 的概率依赖第 1、2 个 token；
  • 如果第 2 个草稿 token 被拒绝并替换成了别的，那么第 3 个候选就不再可靠——它是在包含旧第 2 个 token 的上下文里生成的，而现在上下文已经"换了地基"；
  • 所以一旦中间某个位置被替换，后面的草稿 token 必须全部丢掉，下一轮从新上下文重新猜。这不是算法保守，而是条件分布已经改变。

序列级一致性因此是单 token 证明的反复套用：前面的 token 都被接受时，当前位置的上下文与目标模型直接采样时一致 → 在此上下文中单 token 的拒绝采样证明成立 → 一旦拒绝并重采样，当前 token 已经服从目标分布，后续在新上下文重新开始。沿着链式法则走下去，整段序列的联合分布与目标模型自回归采样一致。

（2）如何验证

  • 统计检验：Leviathan 等（2023）提出用卡方检验等方法，比较两套解码器大量输出的 n-gram 频率分布——分布不可区分则通过；
  • 经验验证：工程上最简单的方式是贪心模式下逐 token 比对——实现正确时，投机解码与 vanilla 的输出逐 token 完全相同（附录 A.1 的 AIInfra 实验正是这样验证"生成文本完全一致"的）；
  • 实现审计：检查拒绝规则用的是否是真实的 p、q（而不是阈值或启发式），是否处理了 q=0 的除零与温度缩放。

（3）与量化、蒸馏的本质区别

量化（INT8/FP8/INT4）和蒸馏是确定性近似——权重被改动，输出分布必然偏移，只是"偏移小到可接受"；投机解码没有改动任何权重，只是换了一套采样执行顺序，分布严格不变。这也是投机解码可以放心与量化叠加的原因：量化负责"压缩模型"，投机解码负责"加速解码"，两者正交。

（4）生产意义

  • 上线零风险：切换投机解码开关，输出质量评测无需重跑；
  • 可叠加性：与温度、top-p、重复惩罚、结构化约束等任何采样策略正交（温度的影响见 §3.8）；
  • 规模无关：草稿模型水平只影响加速多少，不影响输出对不对——哪怕草稿完全随机，输出分布依然是 p，只是加速接近 1×。

3.7 两个重要的特例

（1）贪心解码（temperature = 0）

此时目标分布 p 退化为 one-hot（argmax 处为 1）。接受规则退化为一个简单判定：草稿 token 是否等于目标模型此刻的 argmax。等于 → 接受（min(1, 1)=1）；不等于 → 拒绝，残差分布只剩 argmax，重采样必然得到它。这等价于"草稿猜对了直接白拿，猜错就纠正"，且此时"无损"升级为逐 token 输出完全相同（比分布相同更强）。

（2）无条件接受（p 为退化分布）

如果目标分布只有唯一合法 token（例如 JSON 语法强制的位置），min(1, p/q) = 1，草稿必然被接受。这解释了为什么在代码补全、JSON 生成、结构化输出等"高确定性"场景里，投机解码的接受率最高。

🧮 无损（Lossless）意味着什么 投机解码不会像量化和蒸馏那样改变生成质量——它只是把"从 p 中采样"的预算从目标模型转移到"目标模型 + 草稿模型 + 拒绝采样"。因此：生成文本的分布与直接跑目标模型完全一致，任何下游评测（包括要求严格一致性的场景）都无需重跑。这也是 EAGLE、Medusa、MTP 等所有主流方案都强调 lossless 的原因。
ℹ️ 温度的影响 接受率强烈依赖采样温度：低温（T ≈ 0.1–0.3）时分布尖锐、草稿容易猜中，接受率可达 70–90%；高温（T ≥ 0.7）时分布平坦、随机性强，接受率会掉到 30–50%。因此生产系统通常在低温场景（代码生成、推理、结构化输出）部署投机解码。温度影响采样的完整机制见 §3.8。

3.8 温度如何影响最终的采样：公式、代码与场景选择

（1）公式：带温度的 softmax

温度 T 的作用只有一个：在 softmax 之前把 logits 整体缩放。它不改变 token 的相对排序，只改变概率分布的锐度。式中 z 是 logits 向量（未归一化分数，与 §3.1 的符号一致；这里不用 u 是为了避免与规则 1 的随机数 u 混淆）：

P(xt = vl | x1, …, xt−1) = exp(zl / T) / Σj exp(zj / T)式 (11)
  • T → 0⁺：logits 被放大到无穷，分布退化为 one-hot（argmax 概率 → 1），即贪婪解码；
  • T = 1：标准随机采样（温度不生效）；
  • T → ∞：logits 被压平到 0，概率趋近均匀分布（纯随机）。

（3）不同场景选什么 T，为什么

选择原则只有一条：任务的信息熵越低（答案越唯一），T 越小；任务越开放（答案越多样），T 越大。T 对生成质量的影响通常非单调——太低会重复/死板，太高会跑题/编造，需要在验证集或人工评测上找到甜点（sweet spot）。

（4）为什么温度直接决定投机解码的接受率

回到 §3.2 的接受规则：草稿 token x 被接受的概率是 min(1, p(x)/q(x))。温度从两端影响它：

  • 低 T（分布尖锐）：p、q 都把质量集中在 argmax 附近。只要草稿模型学得好（argmax 与目标一致），采出来的 x 大概率就是目标的 argmax，此时 p(x) ≥ q(x)，接受概率 ≈ 1。接受率近似退化为单事件：P(argmax_q = argmax_p)，所以能到 70–90%；
  • 高 T（分布平坦）：每个位置都要做一次"逐 token 的 p/q 匹配"。平坦分布下草稿很容易采到目标概率低的 token，p(x)/q(x) 远小于 1 → 拒绝。整个草稿串的期望接受长度 E[min(1, p/q)] 逐位置衰减，接受率掉到 30–50%；
  • 推论：贪心（T=0）时接受条件退化为"argmax 是否相等"（§3.7）；T 越大，投机解码的"确定性红利"越薄。生产上要同时拿质量和加速，就把 T 定在 0.1–0.5——这也是为什么投机解码的主流部署场景是代码、推理、结构化输出。

04 加速比分析：接受率是唯一的杠杆

ACCEPTANCE RATE — WHERE THE SPEEDUP REALLY COMES FROM

4.1 期望接受长度

设每个位置草稿被接受的概率为 α（接受率，acceptance rate），投机长度为 γ。每轮验证时，连续接受的 token 数期望为：

τ = (1 − αγ+1) / (1 − α)式 (12)

这个公式分两步推导——先写出前进量的分布，再用"尾概率求和"把它变成等比数列：

（1）本轮前进量 T 的分布

一轮验证 γ 个候选位置，从左到右检验，前进量 T 只有两类结局：

前进量 T发生条件概率
t 个（1 ≤ t ≤ γ）前 t−1 个候选接受、第 t 个被拒（重采样修正产出第 t 个）αt−1 × (1−α)
γ+1 个全部 γ 个候选接受 + 奖励 token（bonus 直接采自目标分布 p，必然得）αγ

（2）期望 = 尾概率之和

先明确"期望"是什么：期望（expected value）= 加权平均——每个可能取值 × 它的概率，全部加起来：E[T] = Σ t·P(T=t)。"期望"不是"希望"，而是"平均而言"：长期重复很多轮，每轮前进数的平均值（大数定律保证频率收敛到它）。类比掷骰子：期望 = 1×1/6 + 2×1/6 + … + 6×1/6 = 3.5——"掷很多次平均约 3.5 点"，虽然单次永远掷不出 3.5。

为什么可以换成"尾概率之和"：Σ t·P(T=t) 与 Σ P(T≥t) 是同一笔账的两种算法——把定义式展开，P(T=t) 会在 P(T≥1)、P(T≥2)、…、P(T≥t) 中各出现一次（共 t 次），所以"横着加（取值×概率）"等价于"竖着加（至少到达概率累加）"：

E[T] = Σt≥1 P(T ≥ t)尾概率公式（= 定义式的等价变形）

数字验证（γ=5, α=0.8）：定义式 1×0.2 + 2×0.16 + 3×0.128 + 4×0.1024 + 5×0.0819 + 6×0.3277 = 3.69；尾概率式 1 + 0.8 + 0.64 + 0.512 + 0.4096 + 0.3277 = 3.69 ✓——同一个期望，两种算法。

为什么这里用尾概率版：因为 P(T ≥ t) = αt−1 恰好是等比数列（几何概率），求和有闭式解；而定义式 Σ t·αt−1(1−α) 是带 t 的加权和，化简绕圈。同一个期望，哪个视角好算用哪个。而 P(T ≥ t) = 前 t−1 个位置都接受 = αt−1——注意 t = γ+1 时依然成立（前 γ 个候选全接受 + bonus 必得，概率 αγ），奖励 token 被这个公式天然包含：

τ = Σt=1γ+1 αt−1 = 1 + α + α² + … + αγ等比数列，共 γ+1 项

（3）等比数列求和（错位相减）

S = 1 + α + α² + … + αγ，　αS = α + α² + … + αγ + αγ+1两边同乘公比，错开一位
S − αS = 1 − αγ+1　→　τ = S = (1 − αγ+1) / (1 − α)中间 γ 项全部抵消

错位相减的精髓：乘公比后数列整体平移一位，相减时中间所有项一一抵消，只留下首项 1 和越界的尾项 −αγ+1——"γ+1 项求和"被压缩成"两项相减"。数字验证（α = 0.6, γ = 5）：1 + 0.6 + 0.36 + 0.216 + 0.1296 + 0.07776 = 2.38336 = (1 − 0.6⁶) / 0.4 ✓。

边界检查：α → 1 时 τ → γ+1（全部接受 + 奖励 token），α → 0 时 τ → 1（只剩重采样保底的那个 token）。每项 αt−1 的概率含义是"能走到第 t 个位置"（前 t−1 个候选都被接受），把这些概率全部加起来就是期望前进数——这也是为什么 τ(α) 曲线在 α 接近 1 时急速上升（§4.3 模拟器可拖动验证）。

4.2 墙钟时间与盈亏平衡

每轮的墙钟时间 ≈ 草稿阶段耗时 + 目标模型一次前向耗时。设草稿模型与目标模型速度比为 c（例如草稿 20× 快，c = 0.05），加速比近似为：

加速比 ≈ τ / (1 + γ·c)式 (13)
  • α 是分子：接受率越高，每轮拿到的 token 越多；
  • γ·c 是分母成本：草稿阶段越慢、投机越长，代价越大；
  • 盈亏平衡点：业界经验值 α ≈ 0.5–0.6。低于这个值，投机解码在高并发下反而净亏损（每次拒绝都白搭一次目标模型前向）。
💡 由此得到的设计原则
  • ① 一切算法优化的核心目标都是提高接受率 α（而不是盲目加长 γ）；
  • ② 草稿模型必须与目标模型对齐——对齐得越好，α 越高；
  • ③ γ 的选择是"草稿成本 vs 更多候选"的权衡，通常取 3–7；
  • ④ 经验数据：普通独立小模型 α ≈ 0.55–0.70（约 2×）；EAGLE 类 α ≈ 0.70–0.80；EAGLE-2/3 与并行草稿 α ≈ 0.85–0.95（4–6.5×）。

06 经典投机解码：独立草稿模型

THE ORIGINAL — DUAL-MODEL SPECULATIVE DECODING (2023)

6.1 起源与两个奠基工作

投机解码的现代形式由两个团队在 2023 年独立提出，结论几乎相同：

  • Leviathan, Kalman & Matias（Google，Fast Inference from Transformers via Speculative Decoding，arXiv 2211.17192）：正式给出接受率与加速比分析；
  • Chen 等（Accelerating LLM Inference with Staged Speculative Decoding，arXiv 2308.04623）：独立发现同样的采样修正方案。

方案朴素而优雅：用一个独立的小模型（如 125M–1.3B）当草稿，用大模型验证。草稿模型可以完全独立训练，不要求与目标模型有任何共享结构——只要求它"在任务分布上尽量模仿目标模型"。

6.2 完整算法（可实现的最短版本）

import numpy as np

def speculative_generate(draft, target, prefix, gamma=5, temperature=1.0):
    """经典投机解码主循环（示意实现）。
    draft / target : 输入 token 序列、返回下一个位置 logits 的函数
    prefix         : list[int]，当前已生成的前缀
    gamma          : 每轮草稿 token 数（投机长度 K）"""
    while not is_eos(prefix):
        # ── ① 草稿：小模型自回归生成 gamma 个候选 ──
        drafts = []
        for _ in range(gamma):
            logits_q = draft(prefix + drafts)                 # 小模型单步前向
            drafts.append(sample_token(logits_q, temperature))

        # ── ② 验证：大模型一次并行前向，拿到所有位置的真实分布 ──
        logits_p = target(prefix + drafts)                    # 关键：只跑一次！

        # ── ③ 拒绝采样：逐位置检验 ──
        for i, x in enumerate(drafts):
            p = softmax(logits_p[i]); q = softmax(logits_q[i])
            if np.random.rand() < min(1.0, p[x] / q[x]):   # 式 (1) 接受
                continue
            r = np.maximum(0.0, p - q)                        # 式 (2) 残差重采样
            r /= r.sum()
            drafts[i] = sample_from(r)
            break                                     # 首个失败位置停止

        # ── ④ 前进：接受串 + 修正 token（最多 accepted+1 个）──
        accepted = 0
        for x in drafts:
            if verified(x): accepted += 1
            else: break
        prefix.extend(drafts[:accepted + 1])
    return prefix
清单 3 · 经典投机解码核心循环（约 20 行）——草稿、验证、拒绝采样、前进四步

6.3 为什么这个方案很快被超越

双模型方案有两个结构性弱点：

  • ① 能力鸿沟：独立小模型与大模型的知识/能力差距巨大，在复杂推理任务上"猜不中"——接受率 α 往往只有 0.5–0.7；
  • ② 对齐难题：小模型是独立预训练的，其分布 q 与大模型 p 没有约束关系，刻意对齐需要额外蒸馏；
  • ③ 部署成本：需要同时维护两套权重、两个 KV cache，显存开销接近翻倍。

后续所有主流方案（Medusa、EAGLE、MTP、并行草稿）的进化方向高度一致：让草稿"寄生"在目标模型内部——共享它的权重、它的 hidden states、甚至它的 KV cache，从而既获得对齐，又省掉额外权重。

07 零训练方案：n-gram / Prompt Lookup

ZERO-TRAINING DRAFTING — LOOK FOR REPETITION IN THE CONTEXT

7.1 思路：文本会自我重复

Prompt Lookup Decoding（2023，apoorvumang/prompt-lookup-decoding）提出一个几乎"免费"的草稿来源：把当前已生成的后缀当作 n-gram，在 prompt 里找它最近一次出现的位置，把那个位置之后的 token 直接当作草稿。

  • 代码补全：函数调用、模板结构高度重复 → 草稿命中率极高；
  • 长篇续写：重复句式、列表、引用反复出现；
  • JSON / 结构化输出：花括号、引号、字段名循环出现。

为什么叫 n-gram："gram" 源自希腊语 gramma（书写），计算语言学里指"一个语言单元"（词、字符、token）；n-gram 就是连续的 n 个单元组成的序列（1-gram 叫 unigram、2-gram 叫 bigram、3-gram 叫 trigram，如 "我 爱 投机解码" 的 bigram = [我爱, 爱投机解码]）。这个词来自统计语言模型时代——神经网络之前的主流语言模型就是 n-gram 语言模型，用"前 n−1 个词出现后第 n 个词的条件频率"预测下一个词。Prompt Lookup 借用了这个术语：把当前上下文最后 n 个 token 当作"查询 n-gram"，在更早的位置找相同的 n-gram——n 越大匹配越精准但越难命中（长 n-gram 在上下文中出现次数少），n 越小越容易命中但误匹配多，vLLM 默认 5/5 是经验平衡点。

整个过程不需要任何模型、零训练、零额外显存——只需要在上下文里做一次字符串匹配。核心函数只有十几行：

def find_candidate_pred_tokens(input_ids, max_ngram_size, num_pred_tokens):
    """在 input_ids 中找当前后缀的 n-gram 匹配，返回匹配后的延续作为候选草稿"""
    input_length = input_ids.size(1)
    for ngram_size in range(min(max_ngram_size, input_length - 1), 0, -1):
        # 当前最后 ngram_size 个 token 作为查询片段
        query = input_ids[0, -ngram_size:]
        # 在更早的位置滑动搜索相同的片段
        positions = find_overlapping_windows(input_ids[0, :-ngram_size], query)
        if positions:
            match_start = positions[-1] + ngram_size      # 取最近一次匹配
            return input_ids[0, match_start:match_start + num_pred_tokens]
    return torch.tensor([], dtype=input_ids.dtype)
清单 4 · Prompt Lookup 的核心匹配函数（摘自原仓库，略有简化）

匹配范围：只在本条请求的上下文中找。搜索空间是当前请求的 input_ids（prompt + 已生成部分），多轮对话时包括整条对话历史——但绝不跨请求、不跨用户、没有全局索引。所以"代码文件、长文档、重复模板"这类单条上下文内重复多的场景命中率高；不同请求之间的重复（如许多用户问同一个问题）完全利用不到。找不到匹配时函数返回空候选，这一轮退化为普通解码（零风险，不猜就不错）。

匹配查找的开销：时间 O(L·nmax)（L = 上下文长度）——对每个候选 n 在序列上滑动窗口比对，实际实现用向量化（torch.eq 整行比较），1M token 长上下文也只需毫秒级；且每轮投机开始时只匹配一次（一次匹配拿到 γ 个候选再统一验证），相对目标模型每轮一次前向（几百毫秒量级）可忽略（< 1%）；显存开销为零（不加载任何模型、不建索引，直接扫描现有 token 序列）——这是所有草稿方案里成本最低的，也是它"零训练、零显存"定位的来源。

两个参数的区别与联系——它们是 n-gram 投机解码的两个独立旋钮：

  • ① prompt_lookup_min / max（默认 5/5）：匹配参数——决定"查询 n-gram 多长"：取上下文最后 n 个 token 作为查询片段去匹配，n 从 max 向下尝试到 min（找不到就缩短）。n 越大匹配越精准但越难命中；

两者协作：先匹配、后取量——prompt_lookup 决定"拿多长的指纹去找"，num_speculative_tokens 决定"找到后拿多少"。改前者不影响候选数，改后者不影响匹配长度，相互独立。

⚠️ 适用边界 n-gram 方案在代码、结构化输出、长上下文重复文本上效果突出；但在开放式创作、推理链等低重复度文本上接受率很低。它是"零成本垫底方案"——适合作为基线，或与模型类草稿组合使用（比如先用 n-gram 快速命中模板，命不中再交给 EAGLE）。

08 Medusa：多解码头 + 树注意力

MULTIPLE DECODING HEADS WITH TREE ATTENTION (ICML 2024)

8.1 动机：不要第二个模型，加几个"头"

Medusa（Princeton / Together AI / UIUC 等，ICML 2024）提出：与其训练独立草稿模型，不如在目标模型最后一层的 hidden states 上直接挂 K 个轻量解码头。第 k 个头负责预测位置 t+k 的 token。主干模型完全冻结，只训练几个 MLP 头——训练成本与显存开销都极小。

关键创新在于验证阶段：K 个候选可以组成一棵候选树（每个位置取 top-s 个候选，做笛卡尔积组合），Medusa 用修改过的树注意力掩码在一次前向里验证整棵树的所有路径——树中每个节点只关注自己所在分支的祖先，互不干扰。

解码头：shape 与计算范式

输入是主干最后一层的 hidden state h_t（[batch, d_model]，d_model 如 LLaMA-7B 的 4096、Qwen 的 2048–8192），输出是 K 个词表 logits（每个 [batch, |V|]，|V| 如 32k / 128k / 151k）——d_model 维向量映射到词表大小，与主干自己的 LM Head 是同一类投影，只是挂在更浅的位置、各预测一个不同的未来位置。典型实现是 1–2 层小 MLP + 输出投影，且 K 个头共享一个 base、只各留一个独立输出头（省参数，类似多头注意力的共享投影）：

class MedusaHeads(nn.Module):
    def __init__(self, d_model, vocab_size, K, hidden=None):
        super().__init__()
        hidden = hidden or d_model
        self.base = nn.Sequential(              # 共享 base（1–2 层）
            nn.Linear(d_model, hidden),
            nn.SiLU(),
        )
        self.heads = nn.ModuleList([            # K 个独立输出头
            nn.Linear(hidden, vocab_size) for _ in range(K)
        ])

    def forward(self, h_t):                    # h_t: [batch, d_model]
        x = self.base(h_t)                      # [batch, hidden]
        return [head(x) for head in self.heads]  # K × [batch, |V|] logits
清单 6 · Medusa 解码头结构示意（PyTorch）：第 k 个头预测位置 t+k 的 token

参数规模：主要来自输出投影 d×|V|（词表投影没法省）——以 d=4096、|V|=32k 为例，每头输出投影 4096×32000 ≈ 131M，K=3 头 + 共享 base 合计约 426M（7B 主干的 ~6%）；典型配置 medusa_num_heads=3、medusa_num_layers=1（K=3–5 头、1–2 层）。对比：EAGLE 草稿头预测"下一个特征"（d→d），输出投影只有 d×d，所以更小（§9.1 的 ~300–500M）——Medusa 必须输出完整词表分布（每头要独立采样 top-s），输出投影躲不掉。

推理计算链：主干前向取 h_t → K 个头并行算 logits（可 batch 成一次矩阵乘，相对主干前向可忽略）→ 每头 top-s 采样 → 笛卡尔积候选树 → 树注意力一次前向验证（对应图 13）。

笛卡尔积组合：候选怎么拼成完整序列

笛卡尔积（Cartesian product）= 把所有集合的选项"两两全配对"：A × B = {(a, b) | a ∈ A, b ∈ B}。例：{a₁, a₂} × {b₁, b₂} = {(a₁,b₁), (a₁,b₂), (a₂,b₁), (a₂,b₂)}（2×2 = 4 个组合）。在 Medusa 里，K 个头各预测未来一个位置、每个头取 top-s 候选，笛卡尔积就是从每层各取一个、拼成完整序列：

{a₁,a₂} × {b₁,b₂} × {c₁,c₂} × {d₁,d₂} → 2⁴ = 16 条完整候选序列候选路径数 = s^K
  • ① 为什么必须组合：验证需要完整的 token 串——第 2 个位置接受与否依赖第 1 个位置是什么（条件分布，§3.6 链式法则），只给"各层独立候选"不够，必须拼成 (a₁,b₁)、(a₁,b₂)… 这样的具体序列才能验证；
  • ② 与候选树的对应：树的每条路径 = 笛卡尔积的一个元素（16 条叶子路径 = 16 个组合），树注意力掩码保证这些路径互不干扰地一次前向验证完；
  • ③ 生活类比：点套餐——主食 2 选 1 × 饮料 2 选 1 × 甜点 2 选 1 = 8 种套餐。候选树就是"预测套餐"：每层的 top-s 是一道菜的选项，笛卡尔积枚举出所有完整套餐，验证时看哪个最靠谱。

K 个头与 top-s 的关系：深度 × 宽度的两个旋钮

图 13 里有两个参数决定候选树的大小，它们是正交的两个维度——K 管"预测多远"（深度），s 管"每层留几个选项"（宽度）：

参数含义管什么代价
K 个头第 k 个头预测位置 t+k深度：草稿的"远见"越远接受率衰减（离当前上下文越远信息越少，尾部候选几乎随机）
top-s每个头从分布里取概率最高的前 s 个 token宽度：每层的容错树指数膨胀 sK，一次前向验证的路径数爆炸
  • ① 树的形状：深度 = K、宽度 = s，完整路径数 = sK——图 13 中 K=4、s=2 → 理论 2⁴ = 16 条候选路径，树注意力一次前向全部验证，取最长可接受前缀；
  • ② 权衡：两者乘积 = 探索预算，必须一起调——加 K 就得压 s（否则树爆炸），加 s 就得减 K（否则尾部衰减拖累收益）；
  • ③ 退化与典型值：s=1 → 树退化为单一路径（每头只取 argmax 的逐层贪心草稿，失去树结构容错）；典型配置 K=3–5 个头、s=2–3（vLLM 的 medusa_choices 参数即手动指定树形状）。

8.2 训练配方：Medusa-1 与 Medusa-2

  • Medusa-1：冻结主干，只训 K 个头，任意数据集即可（也可用模型自我蒸馏生成数据，适配 RLHF 后的模型）。> 2.2× 加速；
  • Medusa-2：头与主干联合微调（分学习率、头预热），2.3–3.6× 加速；
  • Typical acceptance：以温度阈值替代严格拒绝采样，放宽接受条件，进一步提高接受率（代价是偏离严格无损，工程上常用）；

Typical acceptance（典型接受）详解：用"典型集合"换接受率

与严格拒绝采样的对照——严格版看 p/q 比值（u ≤ min(1, p/q)，数学上保证输出分布 = p，无损）；Typical acceptance 看 p 的绝对水平（候选 token 的温度化概率 ≥ 阈值就放行，不再比较 p/q）：

严格拒绝采样（§3.2）Typical acceptance（Medusa 工程版）
接受条件u ≤ min(1, p(x)/q(x))——看 p 与 q 的比值候选 token 的（温度化）概率 ≥ 阈值（如 posterior_threshold = 0.09）——只看 p 的绝对水平
数学性质输出分布严格 = p（无损）输出分布近似 p（有损但偏差小）
接受率数学上限（由 p、q 决定）更高（放宽条件）

机制：先把目标分布 p 做温度缩放，把概率不低于阈值的 token 划入"典型集合"（模型"认真的候选"）；草稿 token 落在典型集合内 → 直接接受（不再看 p/q 比值）；只有落在集合外的"离谱"token 才走严格拒绝采样。直觉：正常生成时绝大多数 token 都是高概率的"典型 token"（如 "the"、句号、常见词），直接放行，接受率大幅提升。

为什么接受率更高：严格版即使草稿 token 合理（p 不小），只要 q 更大（p/q < 1）就有被拒风险；Typical 版绕开比值比较，避免大量"合理但 p/q < 1"的误拒。

代价与取舍：放行了一些"p 不够高但还算合理"的 token → 输出分布偏离 p（严格说有损，呼应 §3.5 误区 5）；但偏差通常很小——被放宽的 token 在 p 中概率本来不低，文本质量下降难以察觉（Medusa 论文在 MT-Bench 上验证质量不降）。这是用"可忽略的质量偏差"换"显著更高的加速"的工程取舍：追求极致吞吐的生产环境用它，需要严格无损的评测场景用标准拒绝采样。

09 EAGLE 系列：特征层草稿

FEATURE-LEVEL DRAFTING — EAGLE / EAGLE-2 / EAGLE-3

9.1 核心洞察：在"特征空间"而不是"token 空间"猜测

EAGLE（arXiv 2401.15077，SafeAILab，ICML 2024）有一个深刻观察：草稿模型猜不中的根源，是它只能看到 token 级别的表面信息。而目标模型倒数第二层的 hidden states 里，已经编码了"模型正在想什么"的高层语义。

EAGLE 的做法：在目标模型的第二顶层特征上训练一个很小的自回归"特征外推器"：

ft+1 = F(ft, E(xt+1))，　xt+2 ~ LMHead(ft+1)特征级自回归草稿

其中 ft 是目标模型倒数第二层的特征向量，E(xt+1) 是刚生成 token 的 embedding。草稿头 F 只是一两个轻量层，但它在"特征空间"里自回归——每一环都携带目标模型自身的深层语义，因此接受率远高于任何独立小模型。且 F 不预测最终 logits 而预测特征，训练时共享目标的 LM Head，推理时用目标自己的 LM Head 解码 —— 天然对齐。

9.2 完整推理计算链：一轮循环的五个阶段

EAGLE 系列（1/2/3）的推理不是"草稿模型生成 + 目标验证"两个割裂阶段，而是下面这条五阶段循环——每轮循环只付一次目标前向 + γ 次轻量层前向，换来约 γ 个 token 的产出，且每轮保底前进 1 个 token：

  • ① 主干前向（取得特征起点）：当前前缀 x₁…x_t 过目标模型——代价与普通解码完全相同；拿到第二顶层特征 f_t 作为草稿起点。EAGLE-3 改为同时取低/中/高三层特征并剪枝，起点信息更丰富；
  • ② 特征外推循环（轻量层快速串 token，γ 次）：草稿头 F 自回归推进特征：f_{t+i+1} = F(f_{t+i}, E(x′_{t+i+1}))，再用共享 LM Head把 f_{t+i+1} 解码成草稿 token x′_{t+i+2}。特征 f 与 token x′ 同步前移，γ 步串出 x′_{t+1}…x′_{t+γ}。这一步只跑 1 个轻量解码层，几乎不消耗带宽；
  • ③ 拼接 + 一次前向（批量验证）：把草稿序列接到前缀后面，整体喂给目标模型。因果掩码保证这一次前向同时算出全部 γ 个位置的完整分布 p₁…p_γ——与经典投机解码完全相同的"免费午餐"；
  • ④ 逐位拒绝采样（对齐）：从位置 1 到 γ 逐位比较草稿分布 q 与目标分布 p，按 min(1, p/q) 接受；遇到第一个拒绝位置 k 即停，若 k < γ，用残差分布 r ∝ max(0, p − q) 补抽第 k+1 个 token；
  • ⑤ 更新起点（回到 ①）：接受链作为正式输出（保底 1 个 token），以 x_{t+k+1} 为新前缀进入下一轮。

一句话概括这条计算链：草稿阶段用轻量特征外推器低代价串出候选，验证阶段用目标模型一次前向批量"对答案"，更新阶段把已确认的 token 送回上下文——每轮循环只付一次目标前向 + γ 次轻量层前向，换来 γ 个 token 的产出。

EAGLE-2 只改 ② 的展开策略（置信度驱动的动态草稿树），EAGLE-3 只改 ② 的草稿头结构与训练（直接预测 token、多层特征融合、TTT），①③④⑤ 的骨架在三个版本中完全不变。

9.3 EAGLE-2：动态草稿树（EMNLP 2024）

EAGLE-2 不改变训练，只改推理：用草稿模型输出的置信度近似接受率，在草稿阶段动态地决定每一步展开哪些分支（树越深，位置越靠后的节点越不确定），从而在同样算力预算下最大化期望接受长度。无需任何额外训练。

9.4 EAGLE-3：直接预测 token + 多层特征融合 + 训练时测试（NeurIPS 2025）

EAGLE-3 做了三件事，把加速推向新的量级：

  • ① 放弃特征预测，直接预测 token：EAGLE-1/2 在特征空间自回归，训练目标必须拟合特征，限制了扩展性；EAGLE-3 用草稿头直接预测 token logits，解除了"特征预测"约束，从而可以从更多训练数据中获益，形成推理加速的缩放定律（scaling law）；
  • ② 多层特征融合：不再只用第二顶层，而是融合低、中、高三层语义特征（典型取 layer {1, L/2−1, L−4}），让草稿头同时看到局部句法、结构语义与高层意图；
  • ③ 训练时测试（Training-Time Test, TTT）：训练时模拟推理的误差传播——把草稿头自己上一步的输出（而非 ground truth）喂给下一步，使模型对推理时的累积误差免疫，接受率在长草稿序列上不再衰减。

11 并行草稿生成：P-EAGLE / DFlash / DSpark

PARALLEL DRAFTING — THE 2026 WAVE

EAGLE-3 这类方案已经很强了，但它们仍受制于一个结构性约束：自回归草稿——每多投机一个 token，就要多跑一次草稿模型前向。2026 年，Speculators（vLLM 团队）与 vLLM 完整开源了三套并行草稿生成（parallel drafting）算法：P-EAGLE、DFlash、DSpark，把草稿阶段压平成一次前向传播。

11.1 自回归草稿的两堵墙

即便 EAGLE-3 把接受率推到了 0.9 以上，自回归式的草稿生成在生产中仍有两个代价：

  • 模型规模受限：草稿开销随投机长度 K 线性增长——草稿模型被迫做得极小极轻，否则验证阶段省下的时间会被草稿本身吃掉；
  • 运维调参复杂：K 成了一个敏感变量，工程团队必须按场景与实时负载反复精调。

先厘清一个容易混淆的点：Medusa 不也是并行的吗？

是，而且 Medusa 正是"并行草稿"这条路的开创者（与 PARD 并列）。这里的分类维度不是"有没有独立草稿模型"，而是两条正交的轴：

  • ① 草稿阶段是否串行（时间轴）：自回归草稿的每个 draft token 依赖前一个（EAGLE 的特征递归、小模型逐步生成），草稿延迟 ∝ K；并行草稿一次前向同时输出所有位置的候选（Medusa 的 K 个头），草稿延迟与 K 解耦；
  • ② 草稿信息来自 token 还是特征（信息轴）：token 级草稿只看词嵌入（经典小模型、Medusa 的头）；特征级草稿读目标模型的 hidden states（EAGLE 系列，以及 P-EAGLE / DFlash / DSpark）。
草稿方案串行 / 并行token 级 / 特征级
经典双模型（小模型）串行（逐步生成）token 级
Medusa / PARD并行（一次前向 K 头）token 级
EAGLE-1/2/3串行（特征递归）特征级
P-EAGLE / DFlash / DSpark并行（解码头 / 扩散）特征级

所以 Medusa 是"并行 × token 级"，EAGLE 是"串行 × 特征级"，2026 年的三件套是"并行 × 特征级"——把 Medusa 的并行结构与 EAGLE 的特征级质量合二为一。它们的新不在并行本身（Medusa 早已并行），而在三处：① 并行 × 特征级结合，草稿质量贴近 EAGLE；② 并行让草稿网络可以更深更大（深度不再线性增加延迟，每块只跑一次）；③ 补偿并行的固有代价——Medusa 的 K 个头互相独立，位置越靠后、条件越不准确（后缀接受率衰减），DSpark 用 Markov 修正头、DFlash 用双向注意力去噪补上位置间的依赖。

并行的代价在 Medusa 身上已经存在：头与头之间没有依赖——head_k 预测 x_{t+k} 时看不到前 k−1 个位置实际生成了什么。所以 Medusa 才需要候选树（每层 top-s、笛卡尔积组合）来覆盖这种不确定性；这也正是 DSpark 的 Markov 修正头要解决的多模态碰撞问题（"of course" / "no problem" 各自高概率、拼起来却不连贯）。

11.2 三套架构，一条主线

三者都基于验证模型的 hidden states 生成草稿，但注入方式截然不同：

11.3 逐个拆解

P-EAGLE（arXiv 2602.01469）

直接沿用 EAGLE 的思路——把验证模型的 hidden states 当作输入特征——区别在于不再顺序消费这些特征，而是把它们同时映射到多个未来位置，一步输出整串候选。采样采用 COD（Conditional-On-Distribution）机制，让并行分支之间保持分布上的合理条件依赖。训练上实现草稿块稀疏化：沿前瞻维度 K 按衰减比例丢弃 token，把优化算力集中在最关键（最容易被接受）的近端 token 上。

DFlash（arXiv 2602.06036）

对验证模型特征的处理与众不同：先投影、再直接注入草稿模型的 KV cache，而不是作为常规输入喂入。好处有二：草稿注意力可以紧密以验证模型的确切状态为条件；同时不撑大输入序列长度。然后通过 block diffusion（带 mask token 的双向注意力）生成一整块高精度候选。训练上实现序列长度稀疏化：在长度为 N 的序列上沿时间轴随机选取若干锚点，只在这些交叉点计算 block 损失——省下 GPU 显存，同时保持有代表性的覆盖度。两种采样模式由 sample_from_anchor 控制（DFlash 默认：锚点为 bonus token，只训练 mask 位置，产出 block_size−1 个投机 token）。

DSpark（arXiv 2607.05147）：半自回归草稿 + 置信度调度

以 DFlash 并行主干为基座，DSpark 重新设计了投机解码中最关键、最难的一环——草稿生成器。核心是半自回归（semi-autoregressive）架构与系统级调度设计（本节综合 Speculators 文档与糖嘟嘟的AI学习笔记的深度解析）：

① Block-Parallel Backbone（并行主干）：沿用 DFlash 风格一次性生成整个草稿块的特征，草稿延迟与块大小几乎无关，避免 EAGLE 类串行生成带来的 kernel launch 与 KV 管理开销。

② Markov Head（顺序修正头）：解决纯并行草稿的多模态碰撞（multi-modal collision）——上下文后接 "of course" 和 "no problem" 都合理时，纯并行草稿可能在位置 1 选 "of"、位置 2 选 "problem"，拼出 "of problem"：单看每个位置都是高概率 token，组合起来却不连贯。修正机制极轻量：

final_logits_i = base_logits_i + markov_bias_i，　markov_bias_i = f(prev_draft_token)式 (14)

实现是一个低秩 token transition（prev_token_id → embedding(rank=512) → 词表偏置），参数极少；语义是"如果前一个 draft token 是 A，下一个 token 的词表偏置应该怎么变"。它不给块内做完整自回归（没有深层 Transformer 依赖），但足以给并行生成的"骨架"补上局部 token 依赖，显著缓解后缀接受率衰减（DSpark 另支持 RNN Head 建模更长的局部转移）。

③ 与目标模型深度融合：DSpark 不是独立小模型——直接读取目标模型后层 hidden states（开源配置：dspark_target_layer_ids = [58, 59, 60]、dspark_block_size = 5、dspark_markov_rank = 512），"站在 target 内部表征上做短程预测"。草稿与目标分布的 Total Variation 距离天然更小，且无需独立加载额外权重，部署更轻量。

④ 置信度头 + 硬件感知前缀调度：对每个位置估计前缀存活概率 a_k = P(位置 1~k 全部被接受)，用马尔可夫链建模 a_k = ak−1·c_k（c_k 为条件接受概率）；离线分析引擎吞吐曲线 SPS(B)（每秒生成 token 数随批大小的变化），在线按 Θℓ = (1 + aℓ)·SPS(B + ℓ) 选择验证长度 ℓ，剪掉低置信度的后缀 token——发散请求（如开放域聊天）不再浪费验证算力。

⑤ 异步因果屏障（asynchronous causality barrier）：现代推理引擎（CUDA Graph / Zero-Overhead Scheduling）要求下一步的 batch size 提前确定、计算图结构不能每步都变，动态验证长度会直接卡死 GPU 流水线。DSpark 把调度拆成两个时间维度：验证容量上限 K 用"两步前"的历史置信度决定（与当前 token 完全隔离，调度器没有"偷看"，拒绝采样的数学前提不被破坏、无损性保持）；具体选哪 K 个候选则按当前最新置信度排序——"容量靠历史，排序靠当下"。

⑥ 训练设计：位置权重 w_k = exp(−(k−1)/γ) 强调靠前位置（对接受长度的边际贡献更大）；三个损失：交叉熵 ℒ_ce（标准 next-token prediction）、分布匹配 ℒ_tv（直接最小化草稿与目标分布的 TV 距离，理论上最大化期望接受率）、置信度损失 ℒ_conf（训练置信度头估计接受概率）。草稿模型共享目标的嵌入层与 LM Head（冻结），只更新主干、顺序头与置信度头。

⑦ 实测：离线（固定验证长度、关闭调度器）在 Qwen3-4B/8B/14B 上，DSpark 相比 EAGLE-3 提升 26.7–30.9%，相比 DFlash 提升 16.3–18.4%；一个反直觉发现——纯并行草稿在位置 1 的准确率反而高于自回归草稿（并行可以用更深网络），这正是并行路线整体占优的关键。DeepSeek-V4 生产环境（匹配吞吐量下）每用户生成速度提升 60–85%。

HuggingFace Transformers 把投机解码封装成了 generate() 的参数，四种模式开箱即用：

# ① 投机解码：独立草稿模型（经典双模型方案）
out = target.generate(**inputs, assistant_model=draft,
                      do_sample=True, temperature=0.5, max_new_tokens=128)

# ② Prompt Lookup：n-gram 草稿（不需要任何草稿模型）
out = target.generate(**inputs, prompt_lookup_num_tokens=5,
                      max_new_tokens=128)

# ③ 自投机解码：assistant_early_exit 提前退出中间层当草稿
out = target.generate(**inputs, assistant_early_exit=6,
                      max_new_tokens=128)

# ④ 通用辅助解码：tokenizer 都不同的小模型（universal assisted）

13.2 调参清单

  • 投机长度 γ / K：常用 3–7。草稿质量高（EAGLE-3 / 并行草稿）可加大；独立小模型建议 3–5；
  • 温度：低温（0–0.5）时接受率最高；高温采样时投机收益骤降；
  • 树结构（Medusa / EAGLE-2）：fanout 与深度的组合要匹配算力预算——树越宽越深，单次验证越贵；
  • typical acceptance 阈值（Medusa）：放宽接受条件换接受率，注意偏离严格无损的代价；
  • batch 大小：单请求/小 batch 收益最大；大 batch 下转为计算受限，收益递减——上线前务必在目标并发下测；
  • 负载感知：DeepSeek 的做法是按 GPU 负载动态决定验证多少个候选（DSpark 调度器）。

13.3 工程陷阱速查

⚠️ 常见坑
  • GGUF 不兼容：vLLM 中 target 与 draft 都必须是 HuggingFace/transformers 格式；
  • 流水线并行不兼容：speculative decoding 目前无法与 pipeline parallelism 同用；
  • EAGLE 草稿头的 tensor parallel size 必须为 1；
  • MTP 只有单层权重：K ≥ 2 时效果不保证；
  • 草稿 KV cache 显存：并行草稿（双向注意力）的 KV 开销不可忽略，DFlash 用滑动窗口注意力压缩；MLA 系模型（如 Kimi）草稿与目标共享 KV 布局可省管理成本；
  • 基准可比性：报告加速时必须固定温度、batch、max-model-len、硬件，否则数字不可比（Speculators 博客曾因环境配置错误更新过图 1 数据）；
  • 盈亏平衡：接受率低于 ~0.55 时，高并发下投机解码可能净亏损——先测 α 再决定是否上。

# ① 草稿：小模型一次生成多个候选 token
def generate_draft_tokens(generated_tokens, draft_model, tokenizer, max_candidates=5):
    with torch.no_grad():
        generated = draft_model.generate(
            input_ids=generated_tokens.unsqueeze(0),
            max_new_tokens=max_candidates,
            do_sample=True, temperature=0.7,
            pad_token_id=tokenizer.pad_token_id,
            eos_token_id=tokenizer.eos_token_id,
        )
    return generated[0, generated_tokens.shape[0]:]   # 取新生成的候选部分

# ② 验证：拼接后一次前向，同时取目标/草稿在每个位置的分布
all_tokens = torch.cat([generated_tokens, candidate_tokens]).to(device)
target_probs = torch.softmax(target_model(all_tokens.unsqueeze(0)).logits[:, :-1, :], dim=-1)
draft_probs  = torch.softmax(draft_model(all_tokens.unsqueeze(0)).logits[:, :-1, :], dim=-1)

# ③ 拒绝采样：逐位置检验，接受则继续，首个拒绝即中断
p = target_probs[0, prob_idx, cand]
q = draft_probs[0, prob_idx, cand]
q = torch.max(q, torch.tensor(1e-8, device=device))          # 防除零
if torch.rand(1, device=device) < torch.min(torch.tensor(1.0, device=device), p / q):
    accepted_tokens.append(cand)
else:
    break                                          # 一旦拒绝，后续候选不再验证

# ④ 补位：被拒位置用目标模型 argmax 修正，保证每轮至少前进一个 token
if len(accepted_tokens) < len(candidate_tokens):
    next_logits = target_model(generated_tokens.unsqueeze(0)).logits[:, -1, :]
    next_token = torch.argmax(next_logits, dim=-1)
    generated_tokens = torch.cat([generated_tokens, next_token])

A.2　labml.ai 神经网络注释（中文版）：采样技术基础

站点：nn.labml.ai/zh。中文站目前没有投机解码专页；与投机解码最直接相关的是"语言模型采样技术"四篇——贪婪采样、温度采样、Top-K、核采样。投机解码的最后一步（从分布中取 token）正是这些采样器，且拒绝采样的"修正重采样"就是核采样思想在分布差集上的应用：

  • 温度采样（temperature.html）：P(xt = vl | x1, …, xt−1) = exp(zl / T) / Σj exp(zj / T)。T 控制分布锐度：T→0 退化为贪婪，T=1 为普通随机采样，T>1 更平坦。labml 的实现 TemperatureSampler 将 logits 除以温度后用 Categorical 分布采样——投机解码的草稿与验证阶段都遵循同一套采样器接口；
  • 贪婪采样（greedy.html）：温度 0 的极限情形，也是本文 §3.7 中"草稿是否等于 argmax"判定规则的依据；
  • Top-K / 核采样（top_k.html、nucleus.html）：截断采样空间——Medusa 的候选树正是用"每个位置取 top-s"构建的。

A.3　waylandz《LLM Transformer 书》：KV Cache 与解码策略背景

站点：waylandz.com/llm-transformer-book。全书 32 章无投机解码专章，但两处内容构成直接背景：

（1）第 22 章 KV Cache 推理加速

  • 原理：因果模型中旧位置"看不到未来"，只要参数、前缀、位置不变，历史 token 的 K/V 就不变——因此只需缓存，不必每步重算整个 n×n 注意力矩阵；
  • 显存公式：M_KV = 2·B·S·L·H_KV·d_h·b（2 为 K 与 V，B batch，S 缓存长度，L 层数，H_KV KV 头数，d_h 头维度，b 每元素字节）。手算 Llama2-7B（FP16，batch 1，4096 tokens）：每 token 512 KiB，4K 上下文约 2 GiB；
  • Prefill vs Decode：Prefill 并行处理整段 prompt（决定 TTFT），Decode 逐 token 串行（决定 TPOT），小 batch 下"带宽/延迟受限"——投机解码正是在 Decode 阶段用一次并行前向替代多次串行前向；
  • 近亲优化：MQA/GQA 减少 KV 头数（第 23 章）、KV 量化、PagedAttention、滑动窗口/驱逐——均与投机解码的显存与带宽预算直接相关。

（2）附录 B 解码策略详解
