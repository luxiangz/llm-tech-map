AI Infra 自优化（Agentic 优化）· 推理引擎专题 · 2026-10-15

自演进 × 推理引擎 —— 自改进闭环如何优化 LLM 推理系统

分析对象：2025–2026 年把「自演进 / 自改进」（self-evolution / recursive self-improvement）用于 LLM 推理引擎优化的代表性系统——NVIDIA Sol-H3（Recursive Self-Improvement，arXiv:2609.35110）、Meta KernelEvolve（生产级 agentic kernel 进化）、MetaInfer（arXiv:2607.12875，契约知识库演化）、antirez DwarfStar/ds4（引擎即模板）；并以 Husky（编译期特化）、Strata（运行时调度自适应）作为非演进对照路线。

证据标注：V = 论文 / 官方页面明确陈述；R = 合理推断；U = 待核实。本文为公开资料综述，未做源码精读。

⚠️ 时效提示：Sol-H3（arXiv:2609.35110）与 MetaInfer（arXiv:2607.12875）均为 2026 年预印本，尚未经过同行评审；KernelEvolve / Husky / DwarfStar 的数字来自各自官方渠道的自述。引用或落地前请自行复现验证。

TL;DR

自演进把推理引擎优化从「人写代码」变成一个带适应度函数的搜索闭环——LLM 当变异算子，profiler 和数值校验当裁判，被接受的改动成为下一轮的基线。这个闭环在推理引擎上已经跑通三个层面：kernel 与栈配置层（Sol-H3 RSI、KernelEvolve）、引擎代码层（DwarfStar 模板化）、部署知识层（MetaInfer 契约知识库）。它能跑通的前提不是模型多强，而是这个领域恰好具备四个稀缺条件：适应度便宜且无梯度、正确性可机械验证、设计空间不连续且反直觉、基线可累积。而它能不能上生产，取决于护栏而不是搜索能力——固定契约、fail-closed、数值三分类、关源再生验证，这些「不给 agent 作弊空间」的设计才是各家真正的核心贡献。

一、「自演进」是什么：从 autotuning 到 agent 演进

用搜索代替手写，在编译器领域并不新鲜。Triton 的 @autotune、TVM 的 AutoTVM/Ansor 早已把 kernel 优化变成搜索问题——但那是在人事先定义好的参数空间（tile size、num_warps、流水级数）里做网格搜索或贝叶斯优化，变异算子是「调参数」。

LLM agent 改变的是变异算子的表达范围：从「调参数」扩展到「改任意代码决策」——把两个算子融合成一个 kernel、换一种内存布局、把通信从 BF16 降到 INT8、把整个模型写成一个 megakernel。这些决策不连续、组合爆炸、没有平滑结构，恰好是传统搜索空间表达不了、而代码生成天然覆盖的空间。

所谓「自演进」，就是把这条「生成 → 评估 → 反馈 → 再生成」的循环闭环运转起来，并且让接受的成果累积为新基线、让探索的经验沉淀为可复用记忆。极端形式就是 Sol-H3 论文标题里的 Recursive Self-Improvement（RSI，递归自改进）。

二、通用闭环的五个环节

不管哪家系统，骨架都是同一套五环节。下图是以「当前基线 $b$」为起点的完整闭环：

图 1：自演进的通用闭环。①②③ 是主循环，④⑤ 是让它「越跑越聪明」的两条增强回路。

  1. 变异（生成候选）：LLM agent 生成候选实现——kernel 融合方案、内存布局、通信排布、传输精度，乃至整段引擎代码。变异空间从参数空间扩展到了任意代码决策。
  2. 评估（适应度）：编译 → 在真实 shape 上跑 → 量延迟 + 验数值一致性。形式化地，一个候选 $c$ 被接受当且仅当：
    $$\text{accept}(c) \iff \big(\operatorname{latency}(c) < \operatorname{latency}(b)\big) \;\wedge\; \big(d_{\text{num}}(c,\, b) \le \epsilon\big)$$
    其中 $d_{\text{num}}$ 是与参考实现的数值距离（bit-exact 时取 $0$），$\epsilon$ 按数值类别分别设定。适应度便宜、连续、可复现——这是这个领域能跑通演进的前提。
  3. 诊断反馈：不只回答「慢 / 错」，还要回答「为什么」——NCU 等 profiler 判断 memory-bound / compute-bound / occupancy 受限，把「为什么」喂回 prompt 指导下一轮变异。
  4. 记忆：成功策略蒸馏进技能库 / 知识库，失败的证据单独记录，跨任务复用，避免每次从零探索。
  5. 递归：接受的优化累积为新基线；更进一步，搜索轨迹本身反哺训练（演进「演进器」，见 KernelEvolve 的强化飞轮）。

三、Sol-H3 的 RSI：固定契约下的递归自改进

RSI 论文的循环是：每轮提出一个候选实现改动（kernel 融合、内存布局、通信排布、传输精度），profile 其延迟、对照正确性契约验证，然后接受或拒绝——接受的改动成为下一轮搜索的基底，这就是「递归」的含义。V

它的核心贡献其实是护栏设计，而不是搜索算法本身：

  • 固定生成契约（fail-closed）：循环被刻意限制为「在固定生成契约下搜索实现，绝不修改契约本身」。不受约束的自改进 agent 可能悄悄减步数、改数值轨迹来换速度，让加速变得不可归因；这里被拒绝的候选只产出「一次精确测量而非一个模糊判断」，验证不过就不上线——循环失败时是关闭的（fail-closed）。
  • 数值三分类：bit-exact 的布局变换、结构保持但不逐位相同的算术融合、量化近似模式，三类分开验证，不许混在一起蒙混过关。
  • 精度保持贯彻到基线层：LoRA 不做权重合并（合并会改变输出——86.1%–94.4% 的更新会舍位回原 BF16 权重），改用消费端融合，并逐字节对照原生分支验证。V

搜索确实挖出了直觉找不到的东西：V

  • 在 50 个 transformer 块中发现 3 个融合组：residual+RMSNorm+modulation、QK norm+RoPE、SwiGLU，每 GPU 每 pass 省约 178 GB 显存流量；
  • 用 stride-aware 布局 kernel 替换掉一个比参考实现还慢 4.7% 的 naive PyTorch permute；
  • 反直觉发现：GB200 上 16 字节对齐的更大 payload 反而比更小的更快——这类不连续、反直觉的设计点正是搜索强、直觉弱的证据。

结果与边界：RSI 加速的系统优化与算法侧调度（4 步 LoRA 等）合计带来约 30× 加速、约 20% 显存节省——8×B300 上 5 秒视频 18.25 s → 1.653 s（快于实时播放），8×GB200 上 1.434 s。V 但论文明确划了线：范式级决策（两阶段跨分辨率调度、latent adapter 这类「需要范式迁移级直觉」的东西）仍然靠人，RSI 只做「可数学验证的有界工程问题」。代码 Apache 2.0 开源。

四、KernelEvolve：生产级演进闭环与强化飞轮

Meta 的 KernelEvolve（隶属 Ranking Engineer Agent）是目前最完整的工业级实现，五个环节全部到位：V

  • 候选：高层 DSL（Triton、TLX、CuTe DSL、FlyDSL）与底层语言（CUDA、HIP、MTIA C++），覆盖 NVIDIA / AMD GPU、自研 MTIA 芯片和 CPU。
  • 搜索：树搜索引擎用 MCTS + 进化策略，每个候选是树上一个节点；节点内存可配置——继承父代轨迹、对比兄弟分支、或整体重启以逃离局部最优。
  • 知识：检索增强知识库注入硬件文档、正确性约束与优化模式（自研 MTIA 芯片没有任何 LLM 训练数据，全靠这条）；成功策略蒸馏回自演进技能库。
  • 评估：对参考实现做 bitwise 正确性校验 + 性能 profiling（NCU、PyTorch Profiler、TritonBench、MTIA Insight），诊断 memory-bound / compute-bound / occupancy 并把「为什么」喂回 LLM。
  • 工程化：job harness 管理多分钟级编译与基础设施故障，数百候选并行评估，直到命中性能目标 / 预算 / 停滞条件。

最关键的一步是强化飞轮：优化 session 产生的 agentic 轨迹用来后训练更小的专用模型，reward 就是实测 kernel 性能——优化器本身在被优化，效率随时间复利。结果：KernelBench 250 题全通过；广告 Andromeda 模型推理吞吐 +60%（对 torch.compile + 厂商库）；MTIA 上训练吞吐 +25%；生成的 kernel 承载万亿级日请求，搜索树跨模型变体与芯片代际复用。V

五、MetaInfer：演进的是知识，不是代码

MetaInfer 把「模型落到硬件上」这件事交给 LLM agent，但它演进的载体不是 kernel 代码，而是一个契约知识库（Contract Knowledge Base，CKB）——模型结构规约、状态契约、权重映射、失败模式。V

工作流是一个三环嵌套的循环：约束输入 → 覆盖检测 → 代码生成 → 契约审查 → 独立验证 → 失败反馈。覆盖检测决定走哪条路：CKB 覆盖目标配置就走「零参照生成」，不覆盖就进入「知识库演化」——失败分析 agent 记录缺失知识与错误假设，转向增量探索，例如修复过 GatedDeltaNet 的 L2 归一化误用 mean 而非 sum、RMSNormGated 门控顺序颠倒、重复 Q 缩放、KV cache 长度维护等具体错误。V

验证是 L0–L3 分层门禁：路径检查 → 组件测试 → 跨阶段回归 → 端到端证据；接受时还查「真实性」——真权重、真并行路径、不许硬编码输出、不许绕过框架。知识吸收的标准非常硬：关闭源码参考后能独立再生，且 24/24 greedy token 与 HuggingFace 参考轨迹一致，才算 PASS_VERIFIED——一次性探索的上下文被蒸馏成可复用的知识约束，而不是塞进上下文里当原始记录。V

注：v1 正文记录的演化案例为 Qwen3.6-27B / Z200 加速器；arXiv 摘要页另列出 DeepSeek V4 Flash（A800 部署修复）、GLM 5.3 Flash（跨模型知识迁移）、海光 K100AI DCU（异构移植）三段实战。两个版本叙述存在差异，引用时以对应版本原文为准。

六、DwarfStar / Husky / Strata：不靠演进的对照路线

自演进不是唯一解，三个系统给出了清晰的对照组：

  • DwarfStar（ds4）——引擎代码层的「半演进」：antirez 的 C 语言本地推理引擎，官方披露大量借助 AI coding agent 开发，并以「模板」形态发布——集成测试套件（加载 / 推理 / KV 状态 / 服务）就是现成的适应度函数，官方明确鼓励用户拿 coding agent 对着自家硬件继续改。相当于把自演进下放给用户侧执行。只跑自产 GGUF 的少数精选模型（DeepSeek V4/V4.1 Flash、GLM 5.2/5.3 Flash 等），约 2.4 万 star。V
  • Husky——编译期特化，运行时零搜索：Underdog 的 model-specific 引擎，只跑自家 4B Woof 模型（4-bit，约 2.4 GB）。为模型的精确张量形状手写 kernel、权重按 kernel tile 顺序直接落盘（加载零转换）、8-bit KV cache 按 attention 消费布局存储、持久 Metal megakernel。M5 Max 上解码 730 tok/s（比 MLX 快至 4.5×）、prefill 约 5150 tok/s、续聊 TTFT 约 35 ms。一切在构建时定死——唯一沾「自」的是 Flash draft 模型用 Woof 自身输出蒸馏（自蒸馏）。V
  • Strata——运行时在线自适应，代码不变：长上下文分层 KV 缓存，GPU-assisted I/O 消碎片 + cache-aware 请求调度把 I/O 停顿与计算重叠。调度策略在线适应负载，但系统代码本身不演进。TTFT 比 vLLM+LMCache 低至 5×，长上下文比 TensorRT-LLM 快 3.75×。V

这两条静态路线的共同逻辑是：如果问题能被静态分析清楚，就不必付搜索的成本。它们反衬出适用边界——单模型专用引擎可以特化，跨模型、跨硬件、持续新模型的场景才需要演进。

八、为什么推理引擎是这个范式的绝佳试验田

  • 适应度便宜且无梯度：CUDA kernel 不可微，没法梯度下降，但跑一千次量延迟只要毫秒级——演化搜索恰好是「无梯度、可测量」问题的标准解法。
  • 正确性可机械验证：allclose、逐 token 对比 HF 轨迹、bitwise 对照参考实现——杜绝「快但错」静默上线，这是绝大多数软件领域给不了的奢侈条件。
  • 设计空间不连续且反直觉：融合边界、布局、对齐、精度排布的组合没有平滑结构，GB200 上「更大的对齐 payload 反而更快」这类发现，恰好是进化搜索强、人类直觉弱的地方。
  • 基线可累积：每个被接受的 kernel 都是真实资产，不会白搜；搜索树、技能库、契约知识都能跨任务、跨芯片代际复用。

九、局限与护栏

  • 范式级创新仍靠人：Sol-H3 论文自己划线——改调度、改架构这类需要范式迁移直觉的决策，RSI 目前做不了；分工是「确定性、可数学验证的有界工程问题交给 agent，开放式有损设计交给人」。
  • 评估成本在引擎级爆炸：单 kernel 千次微秒级测量很便宜，但引擎级 / 端到端级的候选评估（编译、拉起服务、跑真实负载）成本高一个量级以上，分层验证（L0–L3）就是为控制这个成本。
  • 过拟合 benchmark 是通病：所有搜索系统都可能向评测集过拟合；KernelBench 100% 不等于生产 100%，Meta 的做法是直接用生产模型当评测对象。
  • 护栏不是可选项：固定契约、fail-closed、数值三分类、关源再生验证——这些「不给 agent 作弊空间」的设计决定了加速是否可归因、成果能否上生产。换句话说，自演进系统的核心工程量在裁判席，不在生成器。
